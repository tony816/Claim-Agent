# 06. OA 기반 심사 리스크 체크리스트

> **용도:** 청구항 또는 명세서 초안을 작성한 뒤, `OA_Notice.pdf`에서 반복적으로 확인된 거절이유 유형을 기준으로 심사 리스크를 점검한다.
>
> **자료의 성격:** 이 문서는 개별 OA의 기술내용을 모방하는 자료가 아니라, 거절이유의 공통 패턴을 일반화한 검수 규칙이다. 특정 출원의 등록 가능성을 보증하지 않는다.
>
> **사용 제한:** OA 사건의 구성요소, 수치, 재질, 효과 또는 인용발명 결합을 현재 발명에 가져오지 않는다. 명세서에 없는 사항을 새로 만들지 않는다. 선행기술이 제공되지 않은 상태에서는 신규성·진보성을 `UNVERIFIED`로 표시한다.
>
> **역할 경계:** 독립항에서는 `독립항_작성_성공조건.md`와 통사 검수를 통과한 변경 없는 후보에 추가하는 보충 오류 탐지층이다. 종속항 세트에서는 `DEPENDENT_DESIGN_GATE`, dependent success 및 종속항 통사 검수를 통과한 변경 없는 문언에만 적용한다. `OA_DRAFT_GATE`·`DEPENDENT_OA_DRAFT_GATE`에서는 문언·구조와 현재 허용 기술 원자료의 정합성을 보고, `OA_FINAL_GATE`·`DEPENDENT_OA_FINAL_GATE`에서는 정식 명세서의 뒷받침·실시가능성을 추가로 본다. 검수 중 한정을 직접 수정하지 않는다.
>
> **상태 집계:** 정식 명세서 부재에 따른 제42조제3항 실시가능성·제42조제4항제1호 뒷받침의 `UNVERIFIED — SPEC_NOT_PROVIDED`는 해당 FINAL 게이트만 막는다. 현재 허용 기술 원자료에서 문언과 기술관계의 근거가 확인되면 해당 DRAFT 게이트 PASS와 공존할 수 있다. 선행기술 미제공에 따른 신규성·진보성 및 `N/I/S: UNVERIFIED`도 비게이팅이며, 종속항의 `TECHNICAL_SOLUTION_CANDIDATE`를 진보성 PASS로 바꾸지 않는다.

## 1. 분석 범위와 빈도

`OA_Notice.pdf`에는 총 134건의 통지서가 포함되어 있다. 이 중 특허출원 132건을 주된 분석대상으로 사용했고, 실용신안 2건은 특허법 조문별 빈도 산정에서 제외하였다. 한 통지서에 복수 거절이유가 함께 포함될 수 있으므로 아래 수치는 중복 집계이다.

| 거절이유 | 특허 OA 건수 |
|---|---:|
| 특허법 제29조제2항: 진보성 | 126 |

| 특허법 제29조제1항제2호: 신규성 | 25 |
| 특허법 제42조제3항제2호: 배경기술 | 22 |

빈도는 위험의 중요도 순위가 아니다. 명확성 오류 하나만으로도 청구항 전체 또는 그 후속 종속항에 거절이유가 파급될 수 있다.

## 2. 위험 등급

### 2.1 BLOCK

제공된 청구항·명세서만으로 직접 확인할 수 있는 명백한 결함이다. 정확한 위치와 돌아갈 선행 단계를 보고하고, 별도 수정 단계에서 반영한 뒤 전체 게이트를 다시 검사한다. 명세서 근거가 부족하면 사용자에게 누락 사실을 알린다.

예: 선행기재 없음, 잘못된 인용항, 카테고리 충돌, 물리적으로 양립하기 어려운 수치, 명세서에 없는 구성의 임의 도입.

### 2.2 REVIEW

법적·기술적 판단 또는 선행기술 대비가 필요한 위험이다. 자동으로 좁히지 말고, 위험 신호와 필요한 확인자료를 제시한다.

예: 단순 결합, 설계변경, 수치범위의 임계적 의의, 발명의 단일성.

### 2.3 UNVERIFIED

판단에 필요한 자료가 제공되지 않은 상태이다.

예: 선행기술이 없어서 신규성·진보성을 판단할 수 없음, 수치범위의 실험자료가 없음, 도면이 없어 배치관계를 확인할 수 없음.

### 2.4 PASS

해당 입력 범위에서 특정 위험이 발견되지 않았다는 뜻일 뿐이다. `PASS`는 특허 가능, 유효 또는 등록 가능을 의미하지 않는다.

---

## 3. 최우선 적용 순위

1. 현재 발명의 원자료와 출원·보정 단계에 따른 허용 근거
2. `독립항_작성_성공조건.md`와 통사 검수의 동일 후보 판정
3. 본 체크리스트의 선행기재, 인용관계, 카테고리, 뒷받침, 실시가능성 및 물리적 정합성 점검
4. 선행기술이 제공된 경우의 신규성·진보성·단일성 위험 점검

스타일가이드나 문체 예시는 OA 판정 근거로 사용하지 않는다. 사용자가 확정한 청구항도 실패 판정에서 면제하지 않으며, 문언은 보존한 채 위험과 최소 수정 방향만 표시한다.

## 4. 필수 검토 절차

### 4.1 입력자료 확인

다음을 먼저 구분한다.

```text
현재 발명의 설명·도면
현재 작성 또는 보정 대상 청구항
사용자가 확정하여 수정 금지한 청구항
선행기술 또는 OA 인용발명
사용자가 요구한 범위: 신규 작성 / 문체 보정 / 심사 대응 / 청구항만 출력
```

자료가 없으면 임의로 보완하지 않는다.

### 4.2 청구항 구조표 작성

각 청구항에 대해 내부적으로 다음 표를 만든다.

```text
청구항 번호
독립항 또는 종속항
발명 카테고리: 장치 / 시스템 / 방법 / 물품 / 제조물 등
직접 인용항
최종적으로 상속되는 독립항
새로 도입된 용어
인용항에서 상속된 용어
말미의 발명 명칭
```

### 4.3 용어·선행기재 레지스트리 작성

모든 `상기`, `각각의`, `복수의`, `제1·제2`, `산출값`, `상태`, `단계`를 역추적한다.

```text
용어가 처음 도입된 청구항
그 용어가 단수인지 복수인지
후속항까지 이어지는 인용경로
동일한 구성의 다른 명칭 사용 여부
도면부호 및 명세서 명칭과의 일치 여부
```

### 4.4 하드 오류 점검

`CLAR`, `DESC`, `SUP`, `FORM` 항목을 먼저 검사한다. 이 단계에서 BLOCK이 남아 있으면 신규성·진보성 판단보다 먼저 처리한다.

### 4.5 선행기술 위험 점검

인용발명 또는 선행조사 결과가 있는 경우에만 구성대비를 수행한다. 선행기술이 없으면 `NOV 전체: UNVERIFIED`, `INV 전체: UNVERIFIED`로 표시한다.

### 4.6 종속항 파급 점검

부모항의 오류가 후속항에 상속되는지, 후속항이 오류가 있는 용어를 다시 사용하는지 확인한다.

### 4.7 수정 제한

이 검수 단계에서는 문언을 직접 수정하지 않는다. 별도 수정 단계에 전달할 수정 후보의 기술적 범위는 다음으로 제한한다.

```text
명세서에 명시적으로 기재된 사항
도면에서 직접 확인되는 사항
사용자가 제공한 확정 기술관계 — 신규 작성에서만 기술 근거로 사용할 수 있으며, 출원 후 보정·심사 대응에서는 최초 출원자료에서 직접 확인되거나 명확히 도출되는 위치가 특정된 경우에만 사용
기존 청구항의 오탈자·인용관계·카테고리 정합화
```

명세서에 없는 구조적 협동관계, 효과, 수치의 임계성 또는 결합동기를 만들어내지 않는다. 수정 후보가 실제 문언에 반영되면 기존 성공조건·통사·OA 판정은 모두 무효이며 변경된 후보를 다시 검수한다.

# 5. 명확성·간결성 체크리스트

## CLAR-01 선행기재 없는 지시어

- **등급:** BLOCK
- **검출 신호:** `상기 A`, `상기 산출 결과`, `상기 제2부재`와 같이 앞선 부분 또는 인용경로에 A가 존재하지 않는다.
- **점검 질문:** 지시 대상이 같은 청구항 앞부분 또는 적법하게 상속된 인용항에 처음 도입되어 있는가?
- **조치:** 최초 도입 위치에서 부정관사형 명칭으로 구성요소를 도입하거나, 필요한 선행기재가 있는 적정 부모항을 인용한다.
- **금지:** 명세서에만 있다는 이유로 청구항의 선행기재 결함을 무시하지 않는다.
- **대표 근거:** 10-2019-0177225, 10-2019-0177801, 10-2021-0124443, 10-2022-0171879.

## CLAR-02 인용경로 밖에서만 도입된 용어

- **등급:** BLOCK
- **검출 신호:** 해당 용어가 다른 종속항에는 있으나 현재 청구항이 그 항을 직접 또는 간접 인용하지 않는다.
- **점검 질문:** 현재 청구항의 실제 인용 트리 안에서 용어가 도입되었는가?
- **조치:** 필요한 선행기재를 모두 가지면서 가장 덜 한정된 부모항을 선택하거나, 명세서 근거가 있으면 현재 항에서 새로 도입한다.
- **금지:** 단순히 번호가 앞선 청구항에 있다는 이유로 선행기재가 있다고 판단하지 않는다.
- **대표 근거:** 10-2019-0137756, 10-2021-0135778.

## CLAR-03 오류의 후속 종속항 파급

- **등급:** BLOCK
- **검출 신호:** 오류가 있는 부모항을 여러 후속항이 인용한다.
- **점검 질문:** 부모항의 불명확한 용어·카테고리·수치가 후속항에도 그대로 상속되는가?
- **조치:** 부모항을 우선 수정하고 전체 자손항을 다시 검사한다.
- **금지:** 거절이유가 직접 지적된 청구항만 고치고 그 후속항을 그대로 두지 않는다.
- **대표 근거:** 10-2019-0177225 등 다수 OA에서 동일 오류가 인용 종속항에 함께 적용됨.

## CLAR-04 청구항 본문과 말미의 카테고리 충돌

- **등급:** BLOCK
- **검출 신호:** 본문은 단계·행위의 연속인데 말미는 장치이고, 또는 장치 구성 나열인데 말미는 방법이다.
- **점검 질문:** 청구항의 실체와 말미 발명 명칭이 같은 카테고리인가?
- **조치:** 장치와 방법을 별도 독립항으로 분리하고, 각 종속항은 같은 카테고리의 부모항만 인용한다.
- **금지:** `시스템 및 방법`처럼 서로 다른 카테고리를 하나의 청구항 말미에 혼합하지 않는다.
- **대표 근거:** 10-2023-0092680, 10-2024-0121458.

## CLAR-05 부모항과 종속항의 발명 명칭·카테고리 불일치

- **등급:** BLOCK
- **검출 신호:** 종속항의 종결 명칭이 부모항과 다르거나, 제품 종속항이 제조방법 독립항을 인용한다.
- **점검 질문:** 종속항이 실제로 부모항의 모든 구성을 포함하면서 같은 발명을 더 한정하는가?
- **조치:** 올바른 독립항으로 인용관계를 변경하거나 별도 독립항으로 작성한다.
- **금지:** 문언상 `제n항에 있어서`만 붙였다는 이유로 적법한 종속항이라고 보지 않는다.
- **대표 근거:** 10-2022-0104722, 10-2023-0072155, 10-2023-0014952, 10-2024-0121458.

## CLAR-06 하나의 청구항에 복수의 대상·방법을 혼재

- **등급:** BLOCK
- **검출 신호:** 서로 다른 두 물건 또는 두 제조방법을 동시에 하나의 청구항 대상으로 삼는다.
- **점검 질문:** 청구항 하나가 하나의 완결된 발명 대상을 명확히 특정하는가?
- **조치:** 대상별 또는 방법별로 독립항을 분리하고 공통 기술적 특징과 단일성을 별도로 검토한다.
- **금지:** 발명의 명칭에 `A 및 B`가 있다는 이유만으로 두 대상을 하나의 청구항에 병합하지 않는다.
- **대표 근거:** 10-2024-0100997.

## CLAR-07 구성요소의 동일성·계층관계 불명확

- **등급:** BLOCK

```text
[REVIEW] INV-07 — 청구항 6의 수치범위는 임계적 의의 자료가 확인되지 않음.
필요자료: 범위 전후 비교자료 또는 기술적 경계 근거.

[UNVERIFIED] 조건 6 / N·I·S — 선행기술이 제공되지 않아 신규성·진보성 및 선행대응 역할은 판단하지 않음.

OA_DRAFT_GATE: PASS
OA_FINAL_GATE: UNVERIFIED — SPEC_NOT_PROVIDED
DRAFT 역구성 진행 가능: YES
FINAL_CLAIM_LOCK 가능: NO
```

위 예시를 하나의 `OA 종합 REVIEW`로 다시 합치거나 `DRAFT 역구성 진행 불가`로 바꾸지 않는다. 이 상태에서는 사용자에게 실행 여부를 묻지 않고 blind snapshot과 picture 비교로 바로 진행한다.

종속항 세트 검수에서는 별도로 다음처럼 출력한다.

```text
DEPENDENT_OA_DRAFT_GATE: PASS
DEPENDENT_OA_FINAL_GATE: UNVERIFIED — SPEC_NOT_PROVIDED
신규성·진보성: UNVERIFIED — PRIOR_ART_NOT_PROVIDED
DRAFT 종속항 역구성 진행 가능: YES
FINAL 종속항 역구성 진행 가능: NO
```

`DEPENDENT_OA_DRAFT_GATE: PASS`는 기술기여 계약과 현재 허용 원자료에 대한 문언 정합성 PASS이며 진보성 PASS가 아니다. 이 상태에서 각 종속항의 blind snapshot과 picture 비교를 수행하고 `DEPENDENT_RECONSTRUCTION_GATE: PASS`를 얻기 전에는 종속항 세트 LOCK을 만들지 않는다.

## 11.2 청구항만 출력하라는 요청

체크리스트는 내부적으로 수행하되, 사용자 요구에 따라 청구항만 출력한다. 정식 명세서만 없고 DRAFT용 기술 원자료가 충분하면 사용자 예외 선택을 묻지 않고 잠정안 작성을 계속한다. DRAFT용 원자료에도 근거가 없어 작성 자체가 불가능한 경우에만 누락된 필수사항을 질문한다.

## 11.3 심사 대응형 요청

- OA에서 지적된 구성과 실제 인용발명의 대응을 먼저 표로 정리한다.
- 차이점의 존재와 차이점의 용이 도출 가능성을 구분한다.
- 보정 없이 다툴 수 있는 쟁점과 보정이 필요한 쟁점을 구분한다.
- 보정은 최초 명세서의 기재범위 안에서만 제안한다.
- 등록 가능성을 이유로 독립항을 필요 이상으로 축소하지 않는다.

# 12. 최종 체크박스

## A. 구조·형식

- [ ] 모든 독립항과 종속항의 카테고리가 명확하다.
- [ ] 종속항의 말미 발명 명칭이 부모항과 일치한다.
- [ ] 모든 종속항이 필요한 선행기재를 포함하는 적정 부모항을 인용한다.
- [ ] 하나의 청구항에 서로 다른 발명 대상 또는 방법이 혼재하지 않는다.

## B. 용어·관계

- [ ] 모든 `상기` 표현의 지시 대상이 인용경로 안에 존재한다.
- [ ] 단수·복수, 제1·제2 및 `각각`의 사용이 일관된다.
- [ ] 구성요소의 상위·하위·동일·별개 관계가 명확하다.
- [ ] 결합·배치·회전·이동의 주체와 대상이 특정된다.
- [ ] 용어·도면부호·명칭이 명세서 전체에서 일치한다.
- [ ] PHYSICAL/HYBRID 문언에서 실제 물체·면, 관찰 단면·기준, 단면 외곽선·윤곽 및 형상 술어의 주체가 구별되고 일반 기계 개발자가 한 번에 도식화할 수 있다.

## C. 수치·물리 정합성

- [ ] 모든 수치에 물리량·단위·기준점이 있다.
- [ ] 상위항과 하위항의 수치가 서로 양립한다.
- [ ] 누적 한정 후에도 실제 구조와 동작이 성립한다.
- [ ] 상품명이나 미정의 등급만으로 구성을 특정하지 않는다.

## D. 설명·뒷받침

정식 명세서가 없으면 아래 항목은 검수 범위에 따라 `OA_FINAL_GATE: UNVERIFIED — SPEC_NOT_PROVIDED` 또는 `DEPENDENT_OA_FINAL_GATE: UNVERIFIED — SPEC_NOT_PROVIDED`로 기록한다. 현재 허용 기술 원자료에 근거가 있는 잠정 청구항의 해당 DRAFT 게이트를 자동으로 REVIEW 처리하지 않는다.

- [ ] 모든 필수구성이 설명 또는 도면에서 직접 확인된다.
- [ ] 기능을 구현하는 구조·배치·제어관계가 기재되어 있다.
- [ ] 청구항과 설명의 작동 의미가 실질적으로 일치한다.
- [ ] 설명·도면·부호 사이에 모순이 없다.
- [ ] 배경기술이 일반론을 넘어 구체적 종래 기술을 제시한다.

## E. 신규성·진보성

- [ ] 선행기술이 없으면 신규성·진보성을 `UNVERIFIED`로 표시했다.
- [ ] 하나의 문헌에 모든 필수구성이 존재하는지 확인했다.
- [ ] 명칭·용도·효과가 아니라 구조와 관계를 비교했다.
- [ ] 도면의 개시도 검토했다.
- [ ] 종속항은 부가한정만 떼지 않고 부모항 체인을 포함한 전체 발명으로 비교했다.
- [ ] 과제·효과의 공통성과 차이뿐 아니라 결합동기·변경 용이성·변경 저해·효과의 예측 가능성을 구분했다.

## F. 종속항 기술기여 계약

- [ ] 각 종속항이 LOCK된 `DC-NN` 후보와 일대일 대응한다.
- [ ] 과제–추가 기술특징–작동·협동 원리–효과가 현재 문언과 원자료에서 닫힌다.
- [ ] 효과·목적·평가 문구가 기술수단을 대신하지 않는다.
- [ ] `DRAWING_ONLY` 또는 승인되지 않은 `FALLBACK_ONLY`가 재유입되지 않았다.
- [ ] 선행기술이 없으면 기술기여 후보와 진보성 UNVERIFIED를 명확히 분리했다.
- [ ] 단순 결합·치환·복수화·재질선택·설계변경 위험을 확인했다.
- [ ] 수치범위의 임계적 의의와 비교자료를 확인했다.
- [ ] 개별 구성의 예상효과를 넘는 협동관계가 있는지 확인했다.

## F. 단일성·최종 검증

- [ ] 복수 청구항군이 공통의 특별한 기술적 특징을 공유한다.
- [ ] 그 공통 특징이 단순한 공지·일반 구성에 그치지 않는다.
- [ ] 부모항의 오류가 후속항에 파급되지 않았는지 전수 확인했다.
- [ ] 사용자 확정 청구항을 임의 수정하지 않았다.
- [ ] 명세서에 없는 구성·수치·효과를 추가하지 않았다.

## 13. 이 체크리스트의 운영 원칙

```text
명백한 형식·명확성 오류는 코드와 위치를 특정해 보고한다.
선행기술이 없으면 신규성·진보성을 단정하지 않는다.
리스크가 있다는 이유만으로 자동 축소하지 않는다.
차별점이 주장된 경우 원자료에 있는 기술적 협동관계로 뒷받침되는지 검사한다.
명세서가 뒷받침하지 않는 차별점은 만들지 않는다.
OA 원문의 문체와 기술내용은 모방하지 않는다.
한정을 생성·승격·삭제하거나 문언을 직접 수정하지 않는다.
문언이 바뀌면 기존 판정을 폐기하고 성공조건·통사 검수부터 다시 수행한다.
```
