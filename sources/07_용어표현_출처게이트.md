# 07. 용어·표현 출처 게이트

> **용도:** 이미 확정된 기술 개념·구성 계층·한정 집합을 한국어 청구항 문언으로 옮길 때, 주요 용어·상투 표현·띄어쓰기의 출처와 선택 이유를 추적하고 프로젝트 소스 원문의 표면 문체를 일관되게 반영하기 위한 게이트다.
>
> **역할 제한:** 이 게이트는 기술적 구성, 관계, 효과, 수치, 재료 또는 권리범위를 만들지 않는다. 현재 발명의 원자료와 DESIGN_GATE가 확정하지 않은 기술내용은 어떤 문체 소스로도 보충하지 않는다.

---

## 1. 핵심 원칙

1. DESIGN_GATE는 먼저 **기술 개념과 구성 계층**을 잠근다. 현재 발명의 원자료나 USER_LOCK에 정확한 명칭이 있는 경우에만 그 표면 용어까지 잠근다.
2. 이미지처럼 명칭이 없는 원자료에서 설계자가 붙인 설명용 이름은 `개념 라벨`일 뿐 최종 청구항 용어가 아니다.
3. claim-drafter는 의미 초안을 고정한 뒤 본 게이트와 스타일가이드를 읽고, 각 주요 개념에 사용할 최종 용어와 표현의 출처를 정한다.
4. 용어·표현 변경이 개념, 구성 계층, 단수·복수, 포함관계 또는 권리범위에 영향을 주면 표면 정리로 처리하지 않는다. `TERM_EXPRESSION_GATE: RETURN_TO_ARCHITECT`로 중지하고 새 `design_revision`을 요구한다.
5. 표면 문언만 달라지고 명제 트리와 범위가 동일한 경우에는 같은 `design_revision`의 새 claim `revision`으로 처리한다.

---

## 2. 표현 출처의 우선순위

최종 용어와 표현은 다음 순서로 선택한다.

1. **USER_LOCK:** 사용자가 정확히 고정한 문언
2. **INVENTION_SOURCE_EXACT:** 현재 발명의 명세서·도면 설명·구성표·사용자 기술 설명에 실제로 기재된 정확한 용어
3. **PROJECT_CANONICAL:** `04_청구항_스타일가이드.md`의 고정·기본 문형과 이 문서의 정규화 규칙
4. **CORPUS_EXACT_FRAGMENT:** 이미 확정된 개념 또는 국소 표현을 대상으로 역사 코퍼스에서 찾은 정확한 표면 조각
5. **NEW_NEUTRAL_TERM:** 위 출처에 적절한 표현이 없어 새로 만든 중립 용어. 반드시 생성 이유와 배제한 후보를 기록한다.

낮은 순위의 표현이 높은 순위의 정확한 문언을 임의로 덮어쓰지 않는다. 다만 높은 순위 문언이 기술적·통사적 하드 게이트에 실패하면 원문은 보존하고 `REVIEW` 또는 `BLOCK` 및 최소 수정 후보를 보고한다.

---

## 3. 허용되는 코퍼스 검색

기존의 국소 통사 검색과 별도로, 본 게이트에서는 **이미 DESIGN_GATE에서 확정된 개념의 표면 명칭·띄어쓰기·형상 술어만** 정확 검색할 수 있다.

허용 예:

- 확정 개념 `판 형태`에 대해 `판 형상`, `평판형`, `판 형태`의 실제 사용 여부 비교
- 확정 관계 `길이 방향`에 대해 `길이방향`과 `길이 방향`의 표기 비교
- 확정 개념 `회전 날개`에 대해 `날개`, `블레이드`의 출처 존재 여부 확인

금지 예:

- 기술분야가 비슷하다는 이유로 전체 청구항이나 구성 계층을 모방
- 코퍼스에 있는 부품·수치·재질·효과를 현재 발명에 추가
- 검색 결과가 많다는 이유만으로 현재 발명 원자료의 정확한 용어를 교체

검색은 각 개념·표현별 정확한 일치 구절과 필요한 최소 문맥만 읽는다. 사용한 구절은 파일, 예시 ID 또는 청구항, 정확한 조각을 기록한다.

---

## 4. 프로젝트 기본 정규화

아래는 USER_LOCK이나 현재 발명 원자료의 정확한 표기가 없는 경우 적용하는 기본값이다.

| 검사 대상 | 기본 표현 | 처리 |
|---|---|---|
| 치수축을 나타내는 `길이방향`, `폭방향`, `두께방향` | `길이 방향`, `폭 방향`, `두께 방향` | 붙여쓴 형태를 정규화한다. |
| 형상을 뜻하는 임의의 `○○형` 합성어 | `○○ 형상으로 형성되는`, `○○ 형상을 갖는` | 소스 원문 근거가 없는 `평판형`, `원반형` 등의 즉석 합성어를 우선 사용하지 않는다. |
| `상기 각 A` | `상기 A 각각은`, `상기 복수의 A는 각각` 등 | 분배 원천·대상·방식이 드러나도록 재구성한다. |
| `A를 매개로`, `A를 통해` | 직접적인 배치·결합·지지·운동 술어 | 기술관계를 숨기는 추상 연결어를 피한다. 직접 관계가 원자료에 없으면 창작하지 않고 근거 미확인으로 둔다. |
| `단면에서 오목면을 포함하는` 등 관찰 단면과 실제 면의 귀속이 겹치는 표현 | 실제 구성·둘레면을 형상 술어의 주체로 두고 단면을 관찰 조건으로 분리하거나, 의도한 대상이 2차원 선이면 `단면의 외곽선·윤곽`을 명시 | 단면·축·가상선은 기준 객체다. 어떤 객체가 형상을 갖는지와 개방 방향을 직접 표시하고, 기술 개념이나 범위가 달라지면 architect로 되돌린다. |
| 동일 개념의 `바닥면·밑면·저면` 등 | 가장 높은 우선순위 소스에 실제로 쓰인 하나의 용어 | 소스가 없으면 후보별 통상 의미와 귀속을 비교하고 선택 이유를 기록한다. |
| 소스에서 찾을 수 없는 새 부품명 | `NEW_NEUTRAL_TERM` | `팔부`처럼 즉석 조어를 무표시로 확정하지 않는다. 개념 경계·상하위 관계와 명명 이유를 기록한다. |

`○○형`을 일률적인 금지어로 보지는 않는다. USER_LOCK, 현재 발명 원자료 또는 승인된 정확한 소스 조각이 있고 의미·범위가 명확하면 유지할 수 있다.

---

## 5. 구성 계층을 바꾸는 용어 변경

다음은 표면 정리가 아니라 설계 변경이다.

- `하나의 날개부가 두 팔부를 포함`에서 `두 개의 날개부가 허브부에 결합`으로 변경
- `구멍`을 별도 최상위 구성에서 허브의 하위 형상으로 변경
- 단수 구성을 복수 구성으로, 또는 복수 구성을 한 쌍·일대일 대응으로 변경
- `지지대`를 단순 형상 명칭에서 회전축 기능을 수행하는 구성으로 변경

이 경우 claim-drafter나 reviewer가 문언을 직접 고치지 않는다. 변경 후보, 원자료 근거, 계층·범위 영향을 기록하고 architect의 새 `design_revision`으로 되돌린다.

---

## 6. TERM_EXPRESSION_GATE 판정

### PASS

- 모든 주요 구성명, 관계 술어, 형상 표현 및 반복 표기에 출처 라벨이 있다.
- USER_LOCK과 현재 발명 원자료의 정확한 용어가 보존되었다.
- 프로젝트 기본 정규화와 승인된 소스 표현에서 벗어난 문언에는 사유가 있다.
- 동의어 혼용, 무표시 즉석 조어, 불필요한 추상 연결어 및 표기 불일치가 0건이다.
- 단면·축·가상선·영역이 있는 PHYSICAL/HYBRID 표현은 실제 물체·면, 관찰 기준, 단면에 나타나는 대상 및 형상 술어의 주체가 구별된다.
- 표현 적용 전후의 개념, 구성 계층, 명제 트리 및 권리범위가 동일하다.

### REVIEW

- 둘 이상의 표면 용어가 가능하고 선택에 사용자 선호 또는 업계 관행 판단이 필요하다.
- USER_LOCK 또는 현재 발명 원자료의 문언이 프로젝트 기본 표현과 충돌하지만 기술 범위는 확정할 수 있다.

### BLOCK

- 동일 구성에 복수 명칭이 사용되거나, 주요 용어의 지시 대상이 확정되지 않는다.
- 출처 없는 표현이 기술관계를 암시하거나 원자료에 없는 관계를 만들어 낸다.

### RETURN_TO_ARCHITECT

- 용어 수정이 구성 계층, 단수·복수, 포함관계, 협동관계 또는 포섭범위를 바꾼다.

`PASS` 외의 상태에서는 syntax 게이트로 진행하지 않는다.

---

## 7. 필수 산출물

각 revision에 다음 표를 남긴다.

| 개념 ID | 확정 기술 개념·계층 | 최종 문언 | 출처 등급 | 정확한 출처 위치·조각 | 배제한 표현 | 범위 영향 | 판정 |
|---|---|---|---|---|---|---|---|

추가로 다음을 기록한다.

- 표기 정규화 목록
- `NEW_NEUTRAL_TERM` 목록과 생성 이유
- 표현 적용 전 의미 초안과 적용 후 청구항의 범위 불변 결과
- `TERM_EXPRESSION_GATE: PASS | REVIEW | BLOCK | RETURN_TO_ARCHITECT`

문언이 한 글자라도 바뀌면 새 claim `revision`으로 이 표와 게이트를 다시 만든다.
