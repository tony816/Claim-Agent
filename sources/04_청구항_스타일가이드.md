# 04. 청구항 스타일가이드

> **용도:** 한국어 특허 청구항의 문체, 문장 리듬, 구성요소 분절, 조사, 연결어 및 종결 형식을 일관되게 적용하기 위한 규칙서이다.
>
> **근거 자료:** `청구항_문체학습용_분야별검색최적화본.md`의 기존 코퍼스 20세트·143개 청구항에서 반복 문형을 추출하였다. 그중 독립항은 23개, 종속항은 120개이나 최신 `독립항_작성_성공조건.md` 통과 여부는 별도 검증되지 않았다.
>
> **규칙의 성격:** 이 문서는 원문 청구항을 그대로 옮긴 문서가 아니라, 기존 예시에서 반복되는 문체를 추출하여 정규화한 후처리 가이드이다. 주골격이나 한정 집합을 만드는 생성 규칙이 아니며 법적 유효성이나 출원 적합성을 보증하지 않는다.
>
> **활성 시점:** `독립항_작성_성공조건.md`에 따라 주골격, 구성 계층, 한정별 근거, 핵심 협동관계 및 최소충분 한정 집합이 확정되고 보조 예시 없는 의미 초안이 작성된 후에만 적용한다. 주요 용어·형상 표현·띄어쓰기는 `07_용어표현_출처게이트.md`와 함께 확정한다.
>
> **사용 제한:** 예시의 기술적 구성, 수치, 재질, 효과, 제어조건을 현재 발명에 가져오지 않는다. 의미, 권리범위 또는 명제 트리를 변경하지 않는 문체·조사·분절·문장부호 정리에만 사용한다.

---

## 1. 규칙 등급

- **[고정]** 이 프로젝트의 기본 출력 형식으로 채택한 규칙이다. 다만 성공조건이나 현재 발명의 원자료와 충돌하면 적용하지 않는다.
- **[기본]** 의미 초안이 확정된 뒤 선택할 수 있는 기본 문체 후보다. 명확성, 명세서 뒷받침, 명제 트리 또는 권리범위와 충돌하면 적용하지 않는다.
- **[선택]** 특정 청구항 카테고리 또는 문장 구조에서만 사용하는 방식이다.

---

## 2. 적용 권한과 순위

1. 사용자의 현재 지시와 작업 경계 및 현재 발명의 원자료
2. `독립항_작성_성공조건.md`의 0단계와 조건 1~9
3. 확정된 기술 개념·구성 계층·명제 트리·권리범위를 변경하지 않는 범위의 `07_용어표현_출처게이트.md`
4. 주골격·구성 계층·최소충분 한정 집합·명제 트리·권리범위를 변경하지 않는 범위의 본 스타일가이드
5. 해결되지 않은 국소 통사 문제에 대해 조건 2·3·9를 재검증한 문장 조각

본 가이드와 성공조건이 충돌하면 성공조건을 따른다. 예시 문체와 현재 발명의 기술내용 또는 명확성이 충돌하면 예시를 사용하지 않는다.

## 3. 문체의 핵심 특성

### 3.1 객관적·구조적·중립적 문체

- **[고정]** 청구항은 설명문이나 효과 설명이 아니라 구성과 관계를 직접 한정한다.
- **[기본]** 목적이나 장점을 직접 주장하지 않고, 그 목적이나 장점을 가능하게 하는 구조·배치·동작 관계를 적는다.
- **[기본]** 광고성·평가성 표현을 사용하지 않는다.

사용하지 않는 표현의 예:

```text
획기적인, 우수한, 최적의, 완벽한, 효과적인, 매우 안정적인,
사용이 편리한, 성능을 극대화하는, 문제를 완전히 해결하는
```

### 3.2 하나의 청구항은 하나의 완결된 문장

- **[고정]** 각 청구항은 마침표 하나로 끝나는 단일 문장으로 작성한다.
- **[기본]** 구성요소를 여러 줄로 나누더라도 문법적으로는 하나의 문장으로 연결한다.
- **[기본]** `이는`, `따라서`, `이를 통해`, `예를 들어`와 같은 설명식 접속문을 청구항에 넣지 않는다.

### 3.3 구성요소 중심의 분절

- **[고정]** 독립항의 최상위 구성요소 또는 방법 단계는 각각 별도 줄에 둔다.
- **[고정]** 각 최상위 구성 뒤에는 세미콜론을 둔다.
- **[기본]** 하나의 줄에는 하나의 최상위 구성요소를 두고, 그 구성요소의 위치·형상·관계·동작을 같은 줄에서 한정한다.

줄바꿈은 표시 형식일 뿐 귀속을 보충하는 수단이 아니다. 모든 줄바꿈을 제거한 평문에서도 같은 주체·대상·명제 트리와 권리범위가 유지되어야 한다.

## 4. 독립항의 기본 형식

### 4.1 장치·시스템·물품 독립항

**[고정] 기본 골격**

```text
【청구항 1】
[제1구성요소의 한정] 제1구성요소;
[제2구성요소의 한정] 제2구성요소;
...
[마지막 전 구성요소의 한정] 마지막 전 구성요소; 및
[마지막 구성요소의 한정] 마지막 구성요소;
을/를 포함하는 [발명의 명칭].
```

적용 규칙:

1. **[고정]** 마지막 구성요소의 바로 앞 구성요소 뒤에 `; 및`을 사용한다.
2. **[고정]** 마지막 구성요소에도 세미콜론을 사용한다.
3. **[고정]** 마지막 줄은 `을 포함하는` 또는 `를 포함하는`으로 시작하여 발명의 명칭으로 끝낸다.
4. **[기본]** `을/를`은 마지막으로 병렬 나열된 구성요소 명칭의 받침 유무에 맞춘다.
5. **[기본]** 발명의 명칭은 청구항 카테고리와 일치시킨다. 장치 구성을 나열한 청구항을 `방법`으로 끝내거나, 방법 단계를 나열한 청구항을 `장치`로 끝내지 않는다.

### 4.2 구성요소의 배열 순서

**[활성 게이트]** 아래 순서는 주골격을 만드는 템플릿이 아니다. 확정된 주골격의 각 명제를 최상위 구성과 관계 문언에 먼저 매핑한 뒤, 그 인과·협동 순서를 보존하는 범위에서만 현재 발명에 맞는 배열 후보를 선택한다.

#### 구조 중심 장치

```text
전체 몸체·지지체
→ 그 내부 또는 그 위에 배치되는 주요 구성
→ 주요 구성과 결합·연동되는 보조 구성
→ 말단 구성 또는 작동 구성
```

#### 센서·구동·제어 결합 장치

```text
대상 또는 본체
→ 측정·감지 구성
→ 가변·구동 구성
→ 정보를 처리하거나 구동을 제어하는 구성
```

#### 유체·가스·노즐 장치

```text
공급 또는 수용 구성
→ 유로·연통 구성
→ 토출·주입·치환 구성
→ 위치 유지·구동·제어 구성
```

#### 촬상·모니터링 시스템

```text
물리적 대상 장치
→ 촬상·감지 구성
→ 정보 수신·저장 구성
→ 분석·표시·예측 구성
```

구성요소의 수를 예시에 맞추기 위해 억지로 늘리거나 줄이지 않는다. 기존 코퍼스의 장치·물품 독립항은 대체로 2개 내지 7개의 최상위 구성요소를 사용하지만, 이는 품질 기준이나 고정 개수 규칙이 아니다.

## 5. 방법 독립항의 기본 형식

### 5.1 순차 단계형

```text
【청구항 n】
[주체가 입력 또는 대상을 처리하는] 제1단계;
[제1단계의 결과 또는 조건에 따라 수행되는] 제2단계;
...
[마지막 전 단계]; 및
[마지막 단계];
를 포함하는 [방법의 명칭].
```

적용 규칙:

1. **[고정]** 각 줄은 `○○ 단계;`로 끝낸다.
2. **[기본]** 단계의 주체, 입력, 처리 및 결과가 식별되도록 쓴다.
3. **[기본]** 단계는 기술적·시간적 또는 논리적 선후관계에 따라 배열한다.
4. **[기본]** 동일 구성요소의 명칭은 대응 장치 청구항과 일치시킨다.
5. **[기본]** 방법 청구항의 말미는 `를 포함하는 [방법명].`으로 끝낸다.

### 5.2 복수 독립항을 사용하는 경우

- **[선택]** 하나의 발명에 대해 시스템과 제어방법, 제조방법과 제조물, 또는 상이한 공정 경로를 별도 독립항으로 작성할 수 있다.
- **[기본]** 각 독립항은 독립된 카테고리를 가져야 하며, 한 독립항의 말미에서 서로 다른 카테고리를 `및`으로 혼합하지 않는다.
- **[기본]** 대응 독립항 사이에서는 동일한 구성과 단계에 동일한 용어를 사용한다.

## 6. 하나의 구성요소를 작성하는 내부 순서

### 6.1 기본 리듬

**[기본]** 하나의 구성요소는 가능한 경우 다음 순서를 문체 후보로 사용할 수 있다. 다만 머리명사 결속, 단일 명제 트리 또는 핵심 협동관계가 약해지면 이 순서를 버리고 절을 재구성한다.

```text
선행 구성과의 위치·결합 관계
→ 형상·구조·배치
→ 다른 구성과의 작용 관계 또는 동작
→ 구성요소 명칭
```

추상 템플릿:

```text
상기 A에 구비되고, B 형태로 형성되며, 상기 C와 결합되어 D를 이동시키는 E;
```

모든 항목을 반드시 넣는 것은 아니다. 현재 구성의 구별에 필요한 항목만 사용한다.

### 6.2 위치·결합 관계를 먼저 두는 경우

다음과 같은 표현으로 선행 구성과의 관계를 먼저 확정한다.

```text
상기 A에 구비되고,
상기 A의 내부에 배치되고,
상기 A의 단부에 결합되고,
상기 A와 연통되고,
상기 A를 관통하고,
상기 A의 일측에서 상기 B와 마주보도록 구비되고,
```

### 6.3 형상·구조를 이어 쓰는 경우

```text
막대 형상을 갖고,
판 형상으로 형성되고,
복수의 관이 텔레스코픽 구조로 형성되고,
둘레를 따라 복수의 개구가 형성되고,
서로 이격되어 배치되고,
```

### 6.4 동작·기능을 마지막에 두는 경우

```text
상기 대상체를 지지하는 지지부;
상기 정보를 수신하고 상태값을 도출하는 처리부;
상기 측정 정보에 따라 상기 구동부의 동작을 제어하는 제어부;
```

기능을 적을 때는 반드시 그 기능을 수행하는 주체와 대상이 드러나야 한다.

### 6.5 단면·기준과 실제 형상 객체를 분리하는 경우

**[고정]** 기하 관찰에 쓰이는 단면, 절단 기준, 축, 방향, 가상선 또는 영역은 관찰·측정·공간 기준이다. 실제 부품이나 면이 그 가상 객체 안에 물리적으로 존재하는 것처럼 쓰지 않는다. 제조·절삭 결과로 생긴 실제 절단면 자체를 청구하는 경우에는 원자료와 설계 계약에서 그 절단면을 실제 물리면으로 별도 잠근다. 먼저 다음 다섯 항목을 분리한다.

```text
실제 물체·면
→ 관찰 단면·기준
→ 단면에 나타나는 외곽선·윤곽
→ 오목·볼록 등 형상 술어의 주체
→ 형상의 방향·개방 대상
```

피해야 할 추상 예:

```text
A는 기준 방향과 직교하는 단면에서 오목면을 포함하는,
```

실제 둘레면이 형상 보유 객체인 경우의 문체 예:

```text
상기 기준 방향과 직교하는 단면에서, 상기 A의 둘레면 중 상기 B에 면하는 부분이 상기 B를 향해 개방된 오목 형상을 갖는,
```

2차원 선 자체가 형상 보유 객체인 경우의 문체 예:

```text
상기 A를 상기 기준 방향과 직교하게 절단한 단면의 외곽선 중 상기 B에 면하는 부분이 상기 B를 향해 개방된 오목 형상을 갖는,
```

위 예시는 기술내용이나 고정 문언의 근거가 아니다. DESIGN_GATE 또는 DEPENDENT_DESIGN_GATE가 실제 면을 잠갔는지, 단면 윤곽을 잠갔는지에 따라 하나만 사용한다.

- **[고정]** 형상 술어의 문법적 주체를 실제 물체·면 또는 명시된 단면 외곽선·윤곽 중 하나로 확정한다.
- **[고정]** `단면에서`는 관찰 조건으로 사용하고, 그 뒤 무엇의 어느 부분이 어떤 형상을 갖는지 문언에 직접 쓴다.
- **[기본]** 양단부·가상선·중앙부·단면영역 같은 보조 표지는 실제 권리 경계를 구별하고 원자료 근거가 있을 때만 유지한다. 표지를 여러 단계 조합해야 기본 형상을 알 수 있다면 일반 기계 개발자의 1회독 도식화가 가능한지 다시 검사한다.
- **[고정]** 이해 가능성을 높인다는 이유로 범위를 바꾸지 않는다. 단순화 전후 포섭범위가 달라지면 스타일 수정이 아니라 새 revision 또는 design revision의 실체 변경이다.

## 7. 구성요소 내부의 하위 구성 나열

### 7.1 하위 구성요소를 포함하는 상위 구성

```text
상기 A와, 상기 B 및 상기 C를 포함하는 D;
```

또는 관계가 긴 경우:

```text
상기 X에 결합되는 A와,
상기 A를 이동시키는 B 및
상기 B의 동작을 제어하는 C를 포함하는 D;
```

적용 규칙:

- **[기본]** 최상위 구성요소 사이에는 세미콜론을 사용하고, 하나의 최상위 구성 내부의 하위 구성 사이에는 쉼표와 `및`을 사용한다.
- **[기본]** 하위 구성 나열이 길어 최상위 구성이 식별되지 않으면 먼저 단일 명제 트리와 권리범위를 보존하는 통사 재구조화를 수행한다. 길이만으로 한정을 종속항으로 이동하지 않으며, 이동은 `독립항_작성_성공조건.md` 조건 8의 역할·근거 판정을 통과한 선택·보충 한정에 대해서만 검토한다.
- **[기본]** 서로 무관한 기능군을 하나의 상위 구성요소 안에 병합하지 않는다.

## 8. `상기`와 선행기재

### 8.1 최초 도입과 재지칭

- **[고정]** 구성요소 또는 대상의 최초 도입에는 원칙적으로 `상기`를 붙이지 않는다.
- **[고정]** 한 번 도입된 구성요소 또는 대상은 이후 동일한 명칭 앞에 `상기`를 붙여 지칭한다.
- **[기본]** 같은 줄에서 최초 도입한 대상도 그 뒤에서 다시 지칭할 때 `상기`를 사용할 수 있다.

예시 구조:

```text
용기가 안착되는 안착부가 구비되는 본체;
상기 용기의 크기를 측정하는 측정부;
```

### 8.2 용어 일치

- **[고정]** 동일한 구성요소에 동의어를 번갈아 사용하지 않는다.
- **[고정]** 최종 구성명·관계 술어·형상 표현은 `07_용어표현_출처게이트.md`의 출처표와 일치시킨다. 설계 단계의 `CONCEPT_LABEL_ONLY`를 무검증 최종 용어로 복사하지 않는다.
- **[기본]** `몸체`, `본체`, `하우징`, `바디` 중 하나를 선택한 뒤 같은 대상을 가리키는 용어를 유지한다.
- **[기본]** `제1`, `제2`는 동일 종류의 구성을 구별할 필요가 있을 때만 사용한다.
- **[기본]** `일측`, `타측`, `상부`, `하부`, `내측`, `외측`은 기준 대상이 명확할 때만 사용한다.

### 8.3 종속항에서 새 구성을 추가하는 경우

새로 도입하는 구성요소에는 최초부터 `상기`를 붙이지 않는다.

```text
상기 A의 일측에 구비되는 B를 더 포함하는 [발명의 명칭].
```

이후의 종속항에서 B를 다시 지칭할 때 `상기 B`를 사용한다.

## 9. 술어 선택 기준

| 한정 목적 | 기본 표현 |
|---|---|
| 존재·설치 | `구비되는`, `설치되는`, `배치되는` |
| 형상·가공 | `형성되는`, `형상을 갖는`, `구조로 형성되는` |
| 결합·접속 | `결합되는`, `연결되는`, `삽입되는`, `체결되는` |
| 유체·공간 관계 | `연통되는`, `수용하는`, `통과하는`, `토출하는` |
| 운동 | `회전시키는`, `승강시키는`, `이송하는`, `왕복시키는` |
| 지지·구속 | `지지하는`, `고정하는`, `이동을 제한하는`, `이탈을 방지하는` |
| 감지·측정 | `감지하는`, `측정하는`, `촬상하는` |
| 정보 처리 | `수신하는`, `도출하는`, `산출하는`, `분석하는`, `저장하는` |
| 제어 | `○○에 따라 △△의 동작을 제어하는` |
| 추가 구성 | `더 포함하는` |

### 9.1 기능적 표현의 사용

- **[기본]** 기능 표현 자체를 금지하지 않는다.
- **[기본]** 기능의 수행 주체, 대상, 입력 또는 관계가 드러나도록 작성한다.
- **[기본]** 단순한 결과만 적지 말고, 명세서가 뒷받침하는 범위에서 위치·결합·구조 또는 처리관계를 함께 적는다.

불안정한 형태:

```text
정렬되도록 하는 정렬부
안정성을 향상시키는 구조
효율을 높이는 제어부
```

상대적으로 명확한 형태:

```text
상기 복수의 대상체의 측면과 접촉하여 상기 대상체의 이동을 제한하는 정렬부
상기 측정값과 기준값을 비교하고 그 비교 결과에 따라 상기 구동부를 정지시키는 제어부
```

### 9.2 `가능한`의 사용

- **[기본]** `삽입 가능한`, `신장 가능한`, `회전 가능한`과 같이 구조적으로 구현되는 능력을 한정할 때만 사용한다.
- **[기본]** `포함할 수 있다`, `구비될 수 있다`, `필요에 따라`와 같은 임의적 표현은 청구항에 사용하지 않는다.

## 10. 조사·접속어·문장부호

### 10.1 `및`

- **[고정]** 독립항의 최상위 병렬 구성 중 마지막 구성 앞에 `및`을 한 번 사용한다.
- **[기본]** 내부 하위 구성의 병렬 나열에서도 마지막 항목 앞에 `및`을 사용하되, 최상위 병렬과 혼동되지 않도록 문장 구조를 분리한다.
- **[기본]** `및`을 연속하여 사용하거나 마지막 구성 앞에 두 번 사용하지 않는다.

### 10.2 세미콜론

- **[고정]** 독립항의 최상위 구성요소 또는 방법 단계의 경계에 사용한다.
- **[기본]** 종속항은 원칙적으로 쉼표로 연결된 하나의 한정문으로 작성한다. 다만 종속항 안에서 상위 구성을 복수의 하위 구성으로 상세히 나열해야 할 때는 독립항형 분절을 사용할 수 있다.

### 10.3 쉼표

- **[기본]** 위치, 형상, 관계, 동작을 순차적으로 연결할 때 사용한다.
- **[기본]** 짧은 수식 사이에 기계적으로 쉼표를 넣지 않는다.
- **[기본]** 쉼표가 많아 주어와 구성요소 명칭이 멀어지면 먼저 하위 구성을 재배열하거나 절을 재구성한다. 쉼표 수나 문장 길이만으로 한정을 종속항으로 이동하지 않는다.

### 10.4 `을/를 포함하는`

- **[고정]** 독립항의 최종 종결구로 사용한다.
- **[기본]** 병렬 나열의 마지막 구성요소 명칭이 받침으로 끝나면 `을 포함하는`, 받침 없이 끝나면 `를 포함하는`을 사용한다.

## 11. 종속항의 문체 형식

### 11.1 기본 형식

```text
【청구항 n】
제m항에 있어서,
상기 A는 [추가 한정]되는 [발명의 명칭].
```

- **[고정]** `제m항에 있어서,`를 별도 줄에 둔다.
- **[고정]** 종속항도 발명의 명칭과 마침표로 끝낸다.
- **[기본]** 인용항의 전체 내용을 반복하지 않고 새로 추가되는 한정만 적는다.
- **[기본]** 하나의 종속항에는 하나의 중심 한정축을 둔다.

### 11.2 기존 구성요소를 구체화하는 형식

```text
상기 A는 B 형상으로 형성되는 [발명의 명칭].
상기 A는 상기 B의 일측에 배치되는 [발명의 명칭].
상기 A의 길이는 상기 B의 폭보다 크게 형성되는 [발명의 명칭].
```

### 11.3 새 구성요소를 추가하는 형식

```text
상기 A의 일측에 구비되는 B를 더 포함하는 [발명의 명칭].
```

### 11.4 기존 구성요소를 하위 구성으로 분해하는 형식

```text
상기 A는 [제1관계를 갖는] B와, [제2관계를 갖는] C를 포함하는 [발명의 명칭].
```

### 11.5 방법 종속항의 형식

```text
상기 제1단계는 [하위 단계]를 포함하는 [방법명].
[조건이 만족되면 수행되는] 단계를 더 포함하는 [방법명].
```

종속항 후보의 기술기여 여부는 `08_종속항_기술기여_게이트.md`, 잠긴 후보의 종속관계와 트리는 `05_종속항_전개패턴_가이드.md`를 따른다. 이 절의 문형 예시는 후보 생성 또는 기술기여의 근거가 아니다.

## 12. 청구항 유형별 문장 리듬

### 12.1 단순 기계 구조

```text
지지체 → 결합체 → 가동체 → 구속·안착체
```

`DEPENDENT_DESIGN_GATE`가 잠근 기술기여 계약에 형상·상대 위치가 포함된 경우 그 기술관계를 정확히 작성하고, 효과 설명은 넣지 않는다. 단순 기계 구조라는 이유만으로 도면 형상이나 위치를 새 한정으로 추가하지 않는다.

### 12.2 다축·이동 기구

```text
기준 몸체 → 제1축 운동 구성 → 제2축 운동 구성 → 말단 작업 구성
```

각 축이 어느 구성의 길이 방향 또는 어느 축과 직교·평행한지 명확히 적는다.

### 12.3 센서·제어 시스템

```text
측정 대상 → 측정부 → 정보 수신·처리부 → 제어 대상 및 제어부
```

측정값, 기준값, 조건, 제어 동작의 순서를 유지한다.

### 12.4 유체·가스 장치

```text
공급원 또는 수용부 → 연통 유로 → 분사·토출 구성 → 방향·배치·제어 구성
```

`연통`, `삽입`, `토출`, `공급`, `충전`의 대상과 방향을 명시한다.

### 12.5 제조방법

```text
소재·전구체 준비 → 형성·가공 → 열처리·접합 → 후처리 → 완성품 형성
```

공정 순서가 기술적으로 필요한 경우 그 순서를 유지하고, 각 단계의 결과물을 다음 단계에서 `상기`로 지칭한다.

## 13. 사용하지 않을 문장 구조

다음은 이 코퍼스의 문체 기준으로 사용하지 않는다.

```text
A는 B일 수 있다.
A는 B를 포함할 수 있다.
필요에 따라 A가 구비된다.
A 등이 설치된다.
A를 통해 우수한 효과를 얻는다.
본 발명은 A를 특징으로 한다.
상술한 바와 같이 A가 구성된다.
```

또한 다음 문제를 피한다.

- 청구항 카테고리와 종결 명칭의 불일치
- 선행기재 없는 `상기 ○○`
- 서로 다른 구성에 동일 명칭 사용
- 동일 구성에 복수 명칭 사용
- 설명식 인과관계와 효과 문구의 삽입
- 명세서에 없는 수치·재질·부품의 보충
- 단순히 예시와 비슷하다는 이유로 예시의 기술 구성을 전용하는 행위

## 14. 활성 전제와 후처리 절차

1. 외부 생성 단계에서 `독립항_작성_성공조건.md`의 0단계와 조건 1·4·2·3·9·8이 적용되고, 선행기술이 제공된 경우에만 조건 6이 검토되었으며, 주골격·구성 계층·한정별 근거·핵심 협동관계·최소충분 한정 집합·기술 개념과 SOURCE_EXACT_TERM이 DESIGN_GATE로 확정되었는지 확인한다. 선행기술이 없으면 조건 6은 `UNVERIFIED`로 남기며 이 가이드가 해당 결정을 대신하지 않는다.
2. `claim-drafter`가 본 가이드와 용어·표현 출처 게이트를 보지 않고 완성한 `revision_status: PRE_STYLE — NOT_GATE_ELIGIBLE` 의미 초안, `meaning_draft_id`, 주골격 대응표 및 단일 명제 트리를 별도 `claim-style-adjuster`가 입력으로 받는다. 없으면 본 가이드를 적용하지 않는다.
3. `claim-style-adjuster`는 `07_용어표현_출처게이트.md`에 따라 주요 용어·관계 술어·형상 표현·띄어쓰기의 출처표를 만들고, 의미·범위 및 명제 트리를 바꾸지 않는 범위에서 위치·형상·관계·동작의 순서, `및`, 세미콜론, 조사, 분절 및 종결 형식을 정리한다.
4. 모든 `상기`의 선행기재, 머리명사 결속, 출처표와 최종 문언의 정확한 일치 및 줄바꿈을 제거한 평문에서의 동일 귀속을 확인한다.
5. 특정된 통사 문제가 남은 경우에만 검증된 예시 조각을 최대 1~2개 참조한다.
6. 스타일 또는 예시 적용 후 조건 4·3·9와 범위 불변시험을 다시 수행하고, 범위에 영향이 있으면 조건 1·4·8도 다시 적용한다. 예시 조각 적용 뒤 어느 재검사라도 통과하지 못하거나 주골격·계층·한정 집합·명제 트리·권리범위가 바뀌면 조각을 폐기하고 예시 없는 의미 초안으로 되돌린다. 모든 점검을 통과한 때에만 `style_record_id`와 `CLAIM_STYLE_GATE: PASS`를 봉인하고 target revision을 success 단계에 넘긴다.
7. 종속항은 DRAFT 또는 FINAL 독립항 LOCK 후 `08_종속항_기술기여_게이트.md`를 먼저 적용하고, `DEPENDENT_DESIGN_GATE: LOCKED`인 후보만 drafter가 PRE_STYLE 의미 초안으로 문언화한다. 그 뒤 claim-style-adjuster가 각 부모항 체인과 목표항에 본 가이드를 적용해 `dependent_style_record_id`와 CLAIM_STYLE_GATE를 봉인한다. `DRAFT_DEPENDENT_SET_LOCK` 결과에는 명세서 뒷받침·실시가능성 미검증 잠정안 표시를 유지하고, `FINAL_DEPENDENT_SET_LOCK` 전에는 출원용 최종 종속항 세트로 표시하지 않는다.
8. USER_LOCK 문언은 명시적 요청 없이 수정하지 않고 실패 위험만 표시한다.

## 16. 프로젝트 에이전트 적용 지침

이 파일은 본 프로젝트의 **후처리 규칙 자료**이며 전담 적용자는 `.claude/agents/claim-style-adjuster.md`다. `claim-drafter`는 이 파일을 읽지 않은 PRE_STYLE 의미 초안만 만들고, 별도 style adjuster가 독립항의 주골격, 구성 계층, 한정별 근거, 핵심 협동관계 및 최소충분 한정 집합이 확정된 뒤 이 파일을 적용한다. style adjuster는 의미·권리범위·명제 트리를 변경하지 않는 문체·조사·분절·문장부호만 정리하며, 예시는 보조 예시 없이 해결되지 않은 국소 통사 문제가 특정된 경우에만 최대 1~2개의 검증된 문장 조각을 참조한다. 스타일 적용 뒤 exact 문언, 변경 대조표, 범위 불변 결과 및 `CLAIM_STYLE_GATE`를 봉인하지 못하면 success·syntax·OA 단계로 넘기지 않는다.
