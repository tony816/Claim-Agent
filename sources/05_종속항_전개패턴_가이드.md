# 05. 종속항 전개패턴 가이드

> **용도:** 독립항의 보호범위를 유지하면서 종속항을 논리적인 가지와 연쇄로 배치하고, 각 종속항의 인용관계와 한정 순서를 결정하기 위한 규칙서이다.
>
> **근거 자료:** 기존 코퍼스 20세트에 포함된 종속항 120개를 분석하였다. 이 중 90개는 독립항을 직접 인용하고, 30개는 다른 종속항을 인용한다. 코퍼스의 최신 독립항 성공조건 통과 여부는 별도 검증되지 않았으며, 관찰된 빈도를 품질 보증이나 의무 규칙으로 취급하지 않는다.
>
> **규칙의 성격:** 이 문서는 기존 코퍼스에서 관찰된 전개 구조를 정규화한 편집 가이드이다. 특정 발명의 권리범위 설계, 신규성·진보성 또는 심사 결과를 보증하지 않는다.
>
> **사용 제한:** 잠정 모드에서는 조건 4가 허용한 명세서 초안·도면·사용자 제공 기술설명·관계표에서 직접 확인되거나 명확히 도출되는 사항만 사용한다. 최종 모드에서는 정식 명세서·도면 또는 최초 출원자료의 근거를 추가 확인한다. 예시의 구성·수치·재질을 현재 발명에 전용하지 않는다.
>
> **활성 시점:** 독립항의 주골격과 문언이 유효한 DRAFT 또는 FINAL 독립항 LOCK으로 봉인된 뒤, `dependent-claim-strategy-architect`가 `08_종속항_기술기여_게이트.md`의 후보별 `DEPENDENT_SOURCE_GATE`, `CAUSAL_CONTRIBUTION_GATE`, `CLAIMABILITY_GATE`를 PASS한 후보를 선별하면 부모항·권리화 축·트리 설계에 사용한다. 그 트리까지 확정되어야 최종 `DEPENDENT_DESIGN_GATE`를 잠글 수 있다. drafter는 `DEPENDENT_DESIGN_GATE: LOCKED` 뒤에만 이 가이드를 다시 사용해 번호와 선행기재를 검증한다. 이 가이드는 후보의 과제·효과를 새로 만들거나 `DRAWING_ONLY`를 승격하지 않는다.

---

## 1. 핵심 원칙

### 1.0 기술기여 후보를 먼저 잠근다

형상·배치·재질·수치라는 한정 유형은 그 자체로 권리화 가치나 진보성 근거가 아니다. 트리를 설계하기 전에 `08_종속항_기술기여_게이트.md`에 따라 각 후보의 `과제 → 추가 기술특징 → 작동·협동 원리 → 효과`와 원자료 근거를 검증한다. 주된 트리에는 `TECHNICAL_SOLUTION_CANDIDATE`만 배치하고, `FALLBACK_ONLY`는 명시된 보정·실시형태 포섭·침해 입증 가치가 있을 때 별도 보조 축으로 분리한다. `DRAWING_ONLY`와 해결되지 않은 `UNVERIFIED`는 트리에서 제외한다.

### 1.1 가장 넓은 적정 인용항을 선택한다

종속항의 부모항은 단순히 직전 번호가 아니라, **그 종속항을 작성하는 데 필요한 모든 선행 용어와 논리적 전제가 존재하는 가장 넓은 항**으로 선택한다.

```text
부모항 선택 기준 = 필요한 선행기재를 모두 가지면서 가장 덜 한정된 항
```

### 1.2 연쇄는 선행 한정이 반드시 필요할 때만 만든다

- 하위 구성요소가 앞선 종속항에서 처음 도입된 경우
- 앞선 종속항의 조건·산출값·상태를 다음 항에서 다시 사용하는 경우
- 앞선 종속항의 형상이나 위치관계를 더 좁히는 경우
- 앞선 방법 단계의 하위 단계를 다시 세분화하는 경우

위 경우가 아니라면 독립항에서 직접 분기하는 방사형 종속을 우선 검토한다.

### 1.3 서로 다른 권리화 축은 같은 사슬에 억지로 연결하지 않는다

예를 들어 재질 한정과 센서 배치 한정이 서로 전제관계가 없다면, 하나를 다른 하나의 종속항으로 연결하지 않고 독립항에서 별도로 분기한다.

### 1.4 하나의 종속항에는 하나의 중심 한정축을 둔다

하나의 종속항에 복수 내용을 넣을 수 있으나, 그 내용은 동일한 기술적 축을 이루어야 한다.

```text
허용되는 결합: 하위 구성요소 + 그 하위 구성요소의 배치 관계
피해야 할 결합: 재질 + 원격통신 + 별도 구동모드처럼 무관한 세 축의 병합
```

### 1.5 번호가 아니라 논리로 인용한다

종속항 번호를 연속적으로 보이게 하기 위해 불필요한 연쇄를 만들지 않는다. 인용항은 번호 배치 후에도 독립적으로 다시 검토한다.

## 2. 기존 코퍼스에서 관찰된 전개 구조

### 2.1 방사형

```text
청구항 1
├─ 청구항 2: 형상
├─ 청구항 3: 배치
├─ 청구항 4: 재질
└─ 청구항 5: 제어 또는 추가 구성
```

**사용 조건**

- 각 한정이 독립항의 구성만으로 이해 가능하다.
- 한 한정이 다른 한정의 용어나 조건을 전제로 하지 않는다.
- 여러 대체 실시형태를 각각 독립적인 보호축으로 남길 필요가 있다.

**장점**

- 각 종속항이 불필요하게 좁아지는 것을 줄인다.
- 한 분기의 한정이 다른 분기의 권리범위에 섞이지 않는다.
- 종속항 조합 전략을 나중에 다시 설계하기 쉽다.

**기존 코퍼스의 관찰 유형**

- 형상·위치·재질·치수의 병렬 한정
- 센서 위치, 통신, 개폐구조의 병렬 한정
- 노즐의 각도, 배치, 개구 종류, 거리의 병렬 한정

참조 예시: EX-04, EX-08, EX-10, EX-12, EX-17, EX-18, EX-20

---

### 2.2 연쇄형

```text
청구항 1
└─ 청구항 2: 하위 구성 또는 제1조건 도입
   └─ 청구항 3: 그 하위 구성의 관계 또는 제2조건
      └─ 청구항 4: 수치·동작·예외 조건
```

**사용 조건**

- 후행항이 선행항에서 새로 도입된 용어를 사용한다.
- 후행항이 선행항의 산출값·상태·조건을 전제로 한다.
- 구성의 세분화가 `구성 존재 → 배치 → 형상·치수`처럼 계층적으로 진행된다.

**주의점**

- 사슬이 깊어질수록 후행항의 권리범위에 앞선 모든 한정이 누적된다.
- 선행항 하나가 불필요하게 좁으면 후행항 전체가 함께 좁아진다.
- 4단계 이상 깊은 연쇄는 전제관계가 분명한 경우에만 사용한다.

기존 코퍼스에는 최대 7단계 깊이의 기계구조 연쇄가 있으나, 이는 하위 롤러군과 절곡영역이 순차적으로 도입되는 예외적 구조이다. 깊은 연쇄 자체를 문체로 모방하지 않는다.

---

### 2.3 혼합형

```text
청구항 1
├─ 청구항 2
│  └─ 청구항 3
│     └─ 청구항 4
├─ 청구항 5
└─ 청구항 6
```

또는

```text
청구항 1
├─ 청구항 2
│  └─ 청구항 3
├─ 청구항 4
│  └─ 청구항 5
└─ 청구항 6
```

**사용 조건**

- 핵심 한정축 중 일부는 단계적으로 좁혀야 하고, 다른 축은 독립항에서 바로 분기할 수 있다.
- 하나의 발명에 구조축, 제어축, 재질축, 수치축이 함께 존재한다.

**기본 운용**

- 각 권리화 축의 첫 항은 가능한 한 독립항을 직접 인용한다.
- 그 축 안에서만 필요한 후속 한정을 연쇄한다.
- 다른 축으로 넘어갈 때는 다시 독립항 또는 해당 축의 최소 부모항에서 분기한다.

기존 코퍼스에서 자주 관찰되는 구조이나 빈도만으로 현재 발명의 기본값으로 선택하지 않는다. 실제 한정 사이의 전제관계가 맞을 때만 사용한다.

참조 예시: EX-01, EX-02, EX-03, EX-05, EX-06, EX-07, EX-09, EX-11, EX-13, EX-16, EX-19

---

### 2.4 복수 독립항 대응형

```text
청구항 1: 장치 또는 제조방법 독립항
├─ 청구항 2
├─ 청구항 3
└─ 청구항 4

청구항 5: 대응 방법·제품 또는 대체 공정 독립항
├─ 청구항 6
└─ 청구항 7
```

**사용 조건**

- 시스템과 제어방법을 각각 보호할 필요가 있는 경우
- 제조방법과 그 제조물에 각각 독립적인 보호가 필요한 경우
- 서로 양립 가능한 대체 공정 경로가 각각 독립항으로 성립하는 경우

**적용 규칙**

- 각 종속항은 자신과 같은 카테고리의 독립항 또는 그 하위항을 인용한다.
- 방법 종속항이 장치 독립항을 잘못 인용하거나, 제품 종속항이 제조방법 독립항을 잘못 인용하지 않도록 한다.
- 대응되는 구성·단계에는 동일한 용어를 사용하되, 카테고리에 맞게 문장을 바꾼다.

참조 예시: EX-03, EX-14, EX-15

## 3. 종속항 작성 전에 인수하는 한정 목록

`dependent-claim-strategy-architect`가 사용자 자료에서 추출하고 후보별 세 필수 기술기여 게이트를 PASS한 항목을 다음 유형으로 정리해 인수한다. 트리 설계 뒤 최종 `DEPENDENT_DESIGN_GATE`가 잠기며, drafter는 그 잠긴 후보 외의 새 후보를 추출하지 않는다.

| 종속항 유형 코드 | 한정 유형 | 확인 내용 |
|---|---|---|
| DEP-ADD | 구성 추가 | 독립항에 없는 선택 구성요소 |
| DEP-SUB | 구성 세분화 | 독립항 구성요소의 하위 부품 |
| DEP-POS | 위치·배치 | 내부·외부·상하·측방·대향·이격 관계 |
| DEP-JOIN | 결합·연통 | 결합·삽입·관통·연결·연통 관계 |
| DEP-GEO | 형상·구조 | 단면, 곡면, 홈, 돌기, 개구, 텔레스코픽 등 |
| DEP-MOVE | 운동·기능 | 회전, 승강, 이송, 정렬, 지지, 제한 등 |
| DEP-CTRL | 제어·조건 | 측정값, 기준값, 조건판단, 제어동작, 알람 등 |
| DEP-MAT | 재질 | 금속, 수지, 탄성체, 직물 등 |
| DEP-NUM | 수치 | 길이, 각도, 거리, 비율, 범위 등 |
| DEP-ALT | 대안 | 서로 대체 가능한 실시형태 또는 공정 경로 |

`DEP-*`는 종속항 내용을 묶기 위한 분류 코드이며, `독립항_작성_성공조건.md` 조건 8의 `F/E/C/N/I/S` 한정 역할과 서로 다른 체계다. 접두사 없는 단문자 코드를 사용하지 않는다.

각 한정에는 다음 정보를 함께 기록한다.

```text
DC-NN 후보 ID
한정 내용
대상 구성요소
필요한 선행 용어
명세서 근거
해결하려는 기술적 과제
부모항과의 작동·협동 원리
발생 효과
과제 → 추가 기술특징 → 작동·협동 원리 → 효과 인과사슬
청구 가능 의미 한정 패키지
TECHNICAL_SOLUTION_CANDIDATE / FALLBACK_ONLY / DRAWING_ONLY / UNVERIFIED / RETURN_TO_ARCHITECT
DEPENDENT_SOURCE_GATE / CAUSAL_CONTRIBUTION_GATE / CLAIMABILITY_GATE / PRIOR_ART_CONTRIBUTION_GATE
독립항에 필수인지 여부
다른 한정과의 전제관계
권리화 축
```

`DEPENDENT_DESIGN_GATE: LOCKED` 뒤에는 위 목록을 다시 발굴·분류하거나 부모항 전략을 바꾸지 않고, 잠긴 후보와 트리만 문언 작성에 사용한다.

## 4. 권리화 축으로 묶는 방법

### 4.1 하나의 축으로 묶을 수 있는 경우

다음처럼 동일 구성요소를 순차적으로 구체화하는 한정은 하나의 축이 될 수 있다.

```text
구성요소 도입
→ 그 구성요소의 위치·결합
→ 그 구성요소의 형상
→ 상대 치수 또는 수치범위
```

또는

```text
센서의 측정
→ 측정값으로부터 상태값 산출
→ 산출값과 기준값 비교
→ 비교 결과에 따른 구동 제어
```

### 4.2 별도 축으로 분리해야 하는 경우

- 재질 한정이 제어 로직과 무관한 경우
- 카메라 배치가 기계적 체결 형상과 무관한 경우
- 원격통신이 센서 종류와 무관한 경우
- 다른 실시형태에서 독립적으로 채택 가능한 구성인 경우

이 경우 각 축의 첫 종속항은 독립항을 직접 인용하는 방안을 우선 검토한다.

## 5. 부모항 선택 알고리즘

각 종속항마다 다음 순서로 판단한다.

### 단계 1. 종속항에서 사용하는 명사를 표시한다

```text
상기 A, 상기 B, 제1값, 제2상태, 개구, 가이드부 등
```

### 단계 2. 각 명사가 처음 도입된 청구항을 찾는다

- 독립항에 모두 있으면 독립항이 부모 후보이다.
- 특정 명사가 종속항 2에서 처음 도입되면, 그 명사를 사용하는 후행항은 적어도 종속항 2를 인용해야 한다.

### 단계 3. 논리적 전제를 확인한다

용어가 존재하더라도 후행 한정이 특정 조건이나 상태를 전제로 하면 그 조건을 도입한 항을 부모로 삼는다.

예시 구조:

```text
청구항 2: 제1거리값 산출
청구항 3: 제1거리값을 이용한 제2거리값 산출
청구항 4: 제1거리값과 제2거리값의 비교
```

청구항 4는 두 값이 모두 도입된 항을 인용해야 한다.

### 단계 4. 가장 넓은 부모를 선택한다

필요한 선행기재와 전제가 모두 존재하는 후보 중 가장 덜 한정된 항을 선택한다.

### 단계 5. 번호 인접성을 무시하고 다시 검토한다

직전 청구항을 자동 인용하지 않는다. 다른 권리화 축이라면 번호가 떨어져 있어도 독립항을 직접 인용한다.

## 6. 발명 유형별 권장 전개 순서

아래 순서는 고정 규칙이 아니라 `DEPENDENT_DESIGN_GATE`에서 기술기여가 확인된 후보를 각 권리화 축 안에 배열할 때만 사용하는 기본 순서이다. 앞에 적힌 유형이 효과와 무관한데도 순서표를 채우기 위해 추가하지 않는다.

### 6.1 기계·구조 발명

```text
하위 구성요소 도입
→ 선행 구성과의 결합·배치
→ 상대 위치 또는 운동 관계
→ 형상·단면·개구 구조
→ 상대 치수 또는 수치범위
→ 재질
```

재질이 구조의 작동 전제라면 더 앞에 둘 수 있다.

### 6.2 정렬·지지·파지·이송 발명

```text
정렬·지지 구성의 존재
→ 대상체와의 접촉 위치
→ 삽입·안착·구속 관계
→ 이동 또는 이탈 제한 방향
→ 형상·개수·배열
→ 간격·치수·공차
```

### 6.3 센서·제어 발명

```text
측정 대상과 측정 방식
→ 측정 정보 또는 산출값
→ 기준값·조건
→ 조건 판단
→ 구동·잠금·알람·표시 동작
→ 예외 처리 또는 원격통신
```

### 6.4 유체·가스·노즐 발명

```text
공급원·유로·연통 관계
→ 토출구 또는 노즐의 존재
→ 토출 방향·경사·배치
→ 복수 개구의 관계
→ 거리·각도·개수·치수
```

### 6.5 촬상·데이터 처리 발명

```text
촬상·검출 위치
→ 정보 수신·저장
→ 분석 대상과 산출값
→ 표시·시각화
→ 예측·알람·교체 판단
```

### 6.6 제조방법

```text
기본 공정 단계
→ 특정 단계의 하위 공정
→ 공정 조건·온도·시간·재료
→ 대체 공정 경로
→ 제조물의 대응 구성
```

대체 공정이 서로 양립하지 않으면 한 사슬에 넣지 않고 별도 독립항 또는 별도 분기로 작성한다.

## 7. 종속항 문장 패턴

### 7.1 기존 구성의 형상 한정

```text
제1항에 있어서,
상기 A는 B 형상으로 형성되는 [발명의 명칭].
```

### 7.2 기존 구성의 위치·배치 한정

```text
제1항에 있어서,
상기 A는 상기 B의 일측에서 상기 C와 마주보도록 구비되는 [발명의 명칭].
```

### 7.3 하위 구성요소 도입

```text
제1항에 있어서,
상기 A는 B와, C를 포함하는 [발명의 명칭].
```

### 7.4 새 구성요소 추가

```text
제1항에 있어서,
상기 A의 일측에 구비되는 B를 더 포함하는 [발명의 명칭].
```

### 7.5 상대 치수 한정

```text
제m항에 있어서,
상기 A의 길이는 상기 B의 폭보다 크게 형성되는 [발명의 명칭].
```

B가 제m항 또는 그 부모항에 반드시 도입되어 있어야 한다.

### 7.6 조건부 제어 한정

```text
제m항에 있어서,
상기 제어부는 [제1조건]이 만족되면 [제어 대상]을 [제어 동작]시키는 [발명의 명칭].
```

조건에 사용되는 측정값·기준값·상태가 부모항 체인에 도입되어 있어야 한다.

### 7.7 방법 단계 세분화

```text
제m항에 있어서,
상기 A 단계는 B 단계와, C 단계를 포함하는 [방법명].
```

### 7.8 방법 단계 추가

```text
제m항에 있어서,
[A 조건에서 B를 수행하는] 단계를 더 포함하는 [방법명].
```

## 9. 종속항 깊이에 관한 운영 권고

기존 코퍼스의 분포:

```text
독립항 직접 인용: 90개
2단계 깊이: 18개
3단계 깊이: 8개
4단계 이상: 4개
```

운영 원칙:

- **기본값:** 독립항 직접 인용 또는 2단계 내외의 짧은 연쇄
- **3단계 이상:** 하위 구성·조건의 전제관계가 분명할 때 사용
- **4단계 이상:** 다른 가지로 분리할 수 없는지 반드시 재검토
- **깊은 연쇄의 모방 금지:** 예시에 깊은 사슬이 있다는 이유만으로 동일 깊이를 재현하지 않는다

## 11. 종속항 세트의 기본 설계 절차

### 11.1 기술기여 후보 인수

사용할 루트 LOCK의 candidate_id·revision·design_revision·success_record_id·blind_snapshot_id, 용어·표현 출처표, `TERM_EXPRESSION_GATE: PASS`, syntax·OA·역구성 판정과 현재 문언, USER_LOCK, 근거 원자료 및 선행기술 집합이 봉인 기록과 같은지 먼저 확인한다. 이어서 `dependent_set_id`, `dependent_design_revision`, `DEPENDENT_DESIGN_GATE: LOCKED`, 잠긴 `DC-NN` 후보 집합과 의미 한정 패키지가 현재 입력과 같은지 확인한다. 잠정 모드는 유효한 DRAFT 또는 FINAL 독립항 LOCK과 `OA_DRAFT_GATE: PASS`, 최종 모드는 반드시 유효한 `FINAL_CLAIM_LOCK`과 `OA_FINAL_GATE: PASS`가 필요하다. 하나라도 달라졌으면 트리 설계를 중지하고 무효화 범위에 따라 root architect 또는 dependent-claim-strategy-architect로 돌아간다. 이 단계에서 새 선택 구성을 추출하지 않는다.

### 11.2 권리화 축 설정

예:

```text
축 A: 핵심 구성의 결합관계
축 B: 정렬·지지 형상
축 C: 구동·제어
축 D: 재질·수치
```

### 11.3 각 축의 첫 항 설정

각 축의 첫 종속항은 가능한 한 독립항을 직접 인용한다.

### 11.4 축 내부의 전제관계 설정

```text
구성 도입 → 배치 → 형상 → 수치
측정 → 산출 → 판단 → 제어
```

### 11.5 청구항 트리 작성

청구항 문장을 쓰기 전에 내부적으로 다음 표를 작성한다.

| 청구항 | 부모항 | 추가 한정 | 필요한 선행 용어 | 명세서 근거 | 권리화 축 |
|---|---:|---|---|---|---|
| 2 | 1 |  |  |  | A |
| 3 | 2 |  |  |  | A |
| 4 | 1 |  |  |  | B |

사용자가 청구항만 요청한 경우 이 표는 출력하지 않는다.

### 11.6 번호 부여 후 역검증

- 부모항 번호가 존재하는가?
- 부모항보다 후행 번호를 인용하지 않는가?
- 필요한 모든 용어가 부모 체인에 존재하는가?
- 다른 독립항 카테고리의 가지를 잘못 인용하지 않는가?

## 12. 권리범위를 불필요하게 좁히는 패턴

### 12.1 직전항 자동 인용

```text
청구항 2: 재질
청구항 3: 센서 배치
```

센서 배치가 재질을 전제로 하지 않는데도 청구항 3이 청구항 2를 인용하면 불필요하게 범위가 누적된다. 이 경우 청구항 3은 독립항을 직접 인용하는 방안을 우선 검토한다.

### 12.2 서로 다른 실시형태를 한 사슬에 결합

대체 가능한 형상 A와 형상 B를 각각 보호해야 하는데 A를 한정한 항 아래에 B를 배치하면 양립 여부에 따라 모순 또는 불필요한 축소가 생길 수 있다.

### 12.3 수치 한정을 너무 앞에 배치

수치 한정이 뒤의 모든 구조 한정에 반드시 필요한 것이 아니라면, 수치 한정 아래에 다른 권리화 축을 종속시키지 않는다.

### 12.4 약한 부가한정의 반복

독립항에서 직접 분기한 종속항이 모두 단순 재질·일반 센서·통상 형상만 반복하면 종속항 세트의 전략성이 낮아진다. `CAUSAL_CONTRIBUTION_GATE`를 통과하지 못한 단순 형상·배치·수치·재질 후보는 주된 트리에 넣지 않는다. 현재 원자료가 뒷받침하는 범위에서 구체적인 과제를 해결하는 핵심 협동관계, 배치관계 또는 제어관계를 우선 배치한다. 단순 실시형태 보존 가치만 있는 후보는 `FALLBACK_ONLY` 보조 축으로 분리하고 유지 이유를 적는다.

## 13. 하나의 종속항에 복수 한정을 넣는 기준

### 함께 넣을 수 있는 경우

- 두 한정이 동일 구성요소의 하나의 구조를 완성하는 경우
- 한 한정만으로는 문언이 불완전하고 다른 한정이 관계를 특정하는 경우
- 두 한정이 명세서에서 항상 결합된 실시형태로만 제시되는 경우
- 선행기술과 구별되는 협동관계를 함께 나타낼 필요가 있는 경우
- 잠긴 과제–특징–원리–효과 인과사슬이 두 한정을 함께 포함해야만 닫히는 경우

### 분리하는 것이 좋은 경우

- 각각 독립적으로 채택 가능한 경우
- 서로 다른 권리화 축에 속하는 경우
- 하나는 구조이고 다른 하나는 무관한 재질·통신·수치인 경우
- 한정 결합으로 인해 후속 종속항이 지나치게 좁아지는 경우

- [ ] 선행기술이 없는데 신규성·진보성을 PASS로 표시하지 않았는가?

## 15. 권장 내부 출력 형식

본 프로젝트 에이전트는 DRAFT 또는 FINAL lock 후 종속항을 작성하기 전에 내부적으로 다음 순서로 처리한다.

```text
1. LOCK 종류와 식별자·문언·USER_LOCK·근거 자료 집합 유효성 확인
2. dependent_set_id·dependent_design_revision·DEPENDENT_DESIGN_GATE 유효성 확인
3. 잠긴 TECHNICAL_SOLUTION_CANDIDATE와 분리된 FALLBACK_ONLY 인수
4. DRAWING_ONLY·UNVERIFIED 제외 상태 확인
5. 각 한정의 필수 선행 용어 확인
6. 방사형·연쇄형·혼합형 중 구조 선택
7. 청구항 트리 작성
8. 부모항 번호 확정
9. 문장 작성
10. 기술기여 계약 보존·선행기재·모순·카테고리 검수
11. 사용자 요청 형식에 따라 청구항만 출력
```

## 16. 프로젝트 에이전트 적용 지침

이 파일은 본 프로젝트의 **종속항 트리·부모항 설계 규칙 자료**다. dependent-claim-strategy-architect는 DRAFT 또는 FINAL 독립항 LOCK과 후보별 세 필수 기술기여 게이트 PASS 뒤 이 파일로 트리를 설계하고, 그 결과를 포함해 `DEPENDENT_DESIGN_GATE`를 잠근다. drafter는 그 LOCK 뒤 번호·선행기재 검증에만 다시 사용한다. 기술기여 후보의 생성·승격·배제는 `08_종속항_기술기여_게이트.md`가 담당하고, 이 파일은 후보를 재분류하지 않는다. DRAFT 기반 결과는 반드시 `명세서 뒷받침·실시가능성 미검증 잠정안`으로 표시하고, `FINAL_DEPENDENT_SET_LOCK` 전에는 출원용 최종 종속항 세트로 부르지 않는다. 문장 리듬은 잠긴 트리와 기술기여 계약을 바꾸지 않는 범위에서 `04_청구항_스타일가이드.md`로 정리한다.
