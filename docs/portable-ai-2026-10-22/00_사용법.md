# 도구 없는 AI에서 Claim-Agent 컨텍스트 사용하기

이 묶음은 2026-10-22 현재 작업공간의 실행 규칙을, 그래프·자동 루프·서브에이전트가 없는 AI의 단일 응답 절차로 옮긴 것이다. 기존 프로그램의 설정이나 에이전트 파일은 변경하지 않았다.

## 어떤 파일을 넣을까

| 목적 | 넣을 컨텍스트 | 추가로 제공할 것 |
|---|---|---|
| 과제 탐색부터 청구항 작성·자체검수까지 | `01_통합컨텍스트.md` 전체 | 이번 발명의 실제 원자료와 작업 요청 |
| 최상류 과제만 찾기 | `02_invention-problem-finder_전용컨텍스트.md` 전체 | 이번 발명의 실제 원자료 |
| 원 프로그램의 세부 판정 기준까지 더 가깝게 적용 | `01`에 더해 `03_기준전문_선택첨부.md` 첨부 | 파일을 실제 읽을 수 있는 AI 환경 |

`01`에는 `02`의 실행 지침이 이미 전문으로 들어 있다. 둘을 함께 넣을 필요는 없다. 파일 읽기가 불가능한 AI에는 해당 컨텍스트 전문을 직접 붙여 넣는다. 경로만 적어 주는 것으로는 충분하지 않다.

시스템 지침·프로젝트 지침을 지원하면 컨텍스트를 그곳에 넣고, 발명 원자료는 사용자 메시지나 별도 첨부로 제공한다. 지침 칸이 짧으면 컨텍스트를 첫 메시지 또는 읽을 수 있는 지침 파일로 제공한다. 장문 입력을 지원하지 않는 AI에서는 중요 부분이 잘릴 수 있으므로 과제 탐색만 필요할 때는 `02`를 사용한다.

`03`은 선택 사항이다. 실제 사용한 성공조건·용어·스타일·종속항·OA·사전심사 기준의 전문을 한 파일에 모아 두었다. 발명 기술내용을 채우기 위한 자료가 아니다. 미제공 코퍼스·판례·그래프 데이터를 포함한 것으로 간주하지 않는다. 원본 파일 목록과 SHA-256은 `SOURCE_MANIFEST.json`에 있다.

## 바로 붙여 넣을 요청 예시

### A. 원띵 과제만 찾기

```text
위 컨텍스트를 적용해 invention-problem-finder 작업만 수행해줘.
request_mode: PROBLEM_FINDING
problem_scope: INVENTION
USER_LOCK: 없음
USER_PROBLEM: 없음

여러 하류 문제를 함께 만드는 최상류 과제를 찾아줘.
공통 원인이 확인되지 않으면 억지로 하나로 묶지 말고,
자료 부족과 독립된 문제들을 구분해줘.

발명 원자료:
[여기에 실제 발명 설명·종래 문제·구성·작동·효과를 붙여 넣기]
```

### B. 과제 탐색 후 새 독립항 작성

```text
request_mode: AUTHORING_DRAFT
작성 대상: 청구항 1
USER_LOCK: 없음
USER_PROBLEM: 없음
PRIOR_ART_SET: NONE

먼저 원띵 과제 분석을 하고, 그 결과와 원자료를 바탕으로
주골격·핵심 협동관계·최소충분 한정을 정해 독립항 초안을 작성해줘.
중요한 근거와 미해결 사항을 함께 보여줘.

발명 원자료:
[실제 원문 또는 열람 가능한 첨부]
```

### C. 기존 제9항만 수정

```text
request_mode: EXISTING_SET_EDIT
작성 대상: 청구항 9만
수정 금지: 청구항 1~8의 원문과 기존 번호·인용관계
PRIOR_ART_SET: NONE

부모항은 읽기 전용으로 보존하고 제9항만 수정해줘.
추가 특징의 과제–작동 원리–효과에 원자료 근거가 있는지 확인해줘.
부모항 변경이 필요하면 임의 변경하지 말고 이유를 알려줘.

기존 청구항 원문:
[제9항과 정확한 부모항 체인; 필요한 경우 전체 세트]

발명 원자료:
[실제 원문 또는 열람 가능한 첨부]
```

## 출력에서 확인할 핵심

특히 `invention-problem-finder`는 다음이 나오도록 설계했다.

1. 해결수단 없는 최상류 과제와 그 층위.
2. 왜 다른 하류 문제보다 상류인지 2~3문장 설명.
3. `상류 과제 → 원자료의 해결 원리 → 직접 변화 → 하류 문제`의 근거 있는 연결.
4. 인과·지렛대·해결 지점·구조성의 네 검증.
5. 단일 문제, 독립된 여러 문제, 결론 미해결의 구분.
6. 결론을 뒤집을 반증 조건과 필요한 발명자 확인 질문.

AI가 과제 이름을 그럴듯하게 붙였더라도 인과 고리의 근거가 없으면 통과가 아니다. “효율 향상”처럼 효과를 넓게 묶는 것과 실제 공통 원인을 찾는 것을 구분한다.

## 원 프로그램과 차이

근거·관계·인과표로 그래프가 정리하던 정보를 명시하고, 기능별 고정 순서로 역할 분리를 흉내 낸다. 그러나 외부 그래프에서 누락 정보를 검색하거나, 독립 에이전트의 관점 차이를 확보하거나, 실패를 자동으로 반복 수정하는 기능은 재현하지 못한다.

그래서 결과는 `동일 문맥 자체검수 초안`과 `PORTABLE_DRAFT_RECORD`로 표시한다. 원 프로그램의 DRAFT/FINAL LOCK이나 독립 blind PASS로 그대로 가져오지 않는다. 원 프로그램으로 복귀하면 실제 원자료와 현재 문언으로 필요한 게이트를 다시 수행해야 한다.

기존 프로그램과 같은 결과가 나온다는 실증 비교는 수행하지 않았다. 이 묶음은 현재 역할 계약과 판정 기준을 컨텍스트로 이식한 산출물이다.

## 유지·관리

`04_이식대응표.md`는 어떤 원본 규칙을 어떤 방식으로 이식했는지 기록한다. 운영 시 AI에 함께 넣을 필요는 없다. 원본 기준이 바뀌면 이 묶음도 별도 버전으로 갱신하고 과거 자체검수 결과를 자동 재사용하지 않는다.
