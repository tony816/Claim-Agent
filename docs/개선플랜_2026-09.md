# Claim-Agent 개선 플랜 (2026-09)

작성 기준: `main` 최신 커밋 `4f0e3da` 시점의 코드·문서·테스트 전수 검토. 테스트는 `python -m pytest`로 110 passed, 1 skipped 확인.

이 문서는 요청 유형 `META`(프로젝트 설정·구조 감사)의 산출물이며, 청구항 파이프라인 에이전트는 호출하지 않았다.

## 0. 요약

- 파이프라인의 결정론 부기(게이트 계약, revision 해시, blind 격리, 텔레메트리·RCA)는 잘 갖춰져 있고 테스트 110개가 통과한다.
- 가장 큰 공백은 **품질 기준 데이터의 부재**다. eval fixture가 전부 합성 응답이라 9개 역할 프롬프트의 판정이 맞는지 자동으로 확인할 수 없다. CI도 없다.
- 사용자 체감이 큰 공백은 웹 후속 수정이 항상 전체 재설계로 실행되는 점, 실행 예산 상한 부재, PDF·HWP 미지원, 내보내기 부재다.
- 아래 P0(기반) → P1(체감·정확도) → P2(구조) 순으로 진행한다. 계약(`CLAUDE.md`)을 바꾸는 항목은 사용자 승인 뒤 별도 문서로 진행한다.

## 2. 우선순위 근거

### 왜 골든 평가 세트와 CI를 먼저 하는가

1. 역할 파일 드리프트 해소(G3), 웹 revision 분류(G4), 선행기술 단계(G7), 프로바이더 교체(G11), 교훈 주입·thinking_level 실험은 모두 *모델 출력이 바뀌는* 변경이다. 지금은 그 변경이 개선인지 퇴행인지 판정할 기준 데이터가 없다(G1). 기준이 있으면 각 변경을 "골든 세트에서 통과율·주골격 보존·USER_LOCK 보존이 유지되는가"로 같은 잣대에 놓고 비교할 수 있다.
2. `eval run --record/--replay`, `expected.yaml`, shadow 비교, RCA는 이미 코드로 존재한다. 빠진 것은 **데이터**(실제 발명과 기대 결과)와 **자동 실행**이다. 새 인프라를 짓는 일이 아니다.
3. 사용자가 특허 실무자이므로 실제 발명 자료와 기대 청구항을 며칠 안에 제공할 수 있다. 라이브 녹화 비용은 4건 × 1회 수준이다.
4. 한 번 만들면 이후 모든 PR·프롬프트 수정·모델 변경에 재사용된다.

### 왜 웹 revision 분류(G4)와 예산 가드(G5)가 그 다음인가

사용자가 가장 자주 하는 행동은 문언 미세 수정인데, 현재 웹 경로는 그것을 가장 비싼 경로(전체 재설계)로 실행한다. 비용 상한이 없어 실행 전에 얼마가 들지도 알 수 없다. 이 둘은 골든 세트가 있으면 회귀 없이 배포할 수 있는 작은 변경이다.

### 완료 판단 기준

- 골든 케이스 수 ≥ 4, 발명 유형 ≥ 3종.
- CI가 push마다 `pytest` + replay eval을 실행하고, 주 1회 live eval 결과가 `eval/results/`에 쌓인다.
- 이후 프롬프트·엔진 변경 PR은 골든 세트 결과 표를 첨부한다.

#### P1-3. 입력 형식 확장: PDF·DOCX·HWPX·HWP (G6)

  - PDF: `pypdf` 텍스트 레이어; 텍스트가 거의 없으면(스캔본) 명시 거부("OCR 미지원, 텍스트 PDF 또는 이미지로 제공"). 도면 PDF는 `--drawing`으로 지정 시 `pypdfium2`로 페이지→PNG 변환(선택 의존성).
  - DOCX: `python-docx` 문단·표 추출.
  - HWPX: zip 내 `Contents/section*.xml` 파싱(표준 라이브러리만).
  - HWP 5.0: `olefile` + zlib로 `BodyText/Section*` 텍스트 레코드 추출(선택 의존성, 실패 시 HWPX 변환 안내).
  - 추출 결과는 원본 sha256과 함께 `MaterialItem`에 저장하고, 원본 형식·추출기 버전을 `material_meta`에 기록해 `input_revision`에 반영.
- **검증**: 각 형식 최소 샘플 1개로 추출 단위 테스트; 웹 업로드 허용 목록 갱신; `사용법.md` 갱신.
- **규모**: M~L (HWP 5.0 바이너리 처리가 가장 큼; 1차는 PDF·DOCX·HWPX, 2차 HWP).

#### P1-4. 결과 내보내기 (G9)
- **제안**: `claim-agent export <run_id> --format docx|md [--with-evidence]`. 【청구항 N】 형식 본문, 상단에 LOCK 종류·revision·`명세서 뒷받침·실시가능성 미검증 잠정안` 표시, 선택적으로 근거표·게이트 표 부록. 웹 답변에 "DOCX 내보내기" 버튼(`/api/export`).
- **검증**: 생성 파일을 다시 읽어 exact 문언 sha256이 LOCK의 값과 일치.
- **규모**: S~M.
