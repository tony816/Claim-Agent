## 확인한 차이

기존 프로젝트 지침은 이식판의 요약을 세부 기준보다 우선하도록 정했고, 04·05·07·08·성공조건은 `03_기준전문_선택첨부.md` 안에 묶여 있었다. 파일 존재만으로 지침의 우선순위나 실제 적용을 보장할 수는 없다. 문체 코퍼스와 라우팅 인덱스는 프로젝트에 없었다.

따라서 새 기술 규칙을 임의로 만들기보다 폴더의 원본을 개별 소스로 추가하고 적용 순서를 명시했다. 과제 탐색·요청 분류 부분은 변경 전 문언 그대로 보존했다.

## 지침에 직접 명시한 변경

1. 요약보다 개별 원본 기준을 우선한다. 생성은 성공조건, 용어는 07, 범위 불변 문체는 04의 순서를 따른다.
2. 청구항 표시, 하나의 문장, 최상위 구성별 줄바꿈·세미콜론, 마지막 `; 및`, 말미 `을/를 포함하는`을 원문 기준으로 명시한다.
3. 하위 구성은 쉼표·와/과·및으로 묶어 머리명사와 결속하며, 최상위 구성과 같은 분절로 계층을 바꾸지 않는다.
4. 구성 내부는 필요한 범위에서 위치·결합 → 형상·배치 → 작용·동작 → 구성 명칭의 문체를 사용한다. 명확성·근거·기술 의미가 우선한다.
5. USER_LOCK·원자료 정확 표현 → PROJECT_CANONICAL(04·07) → 조건부 코퍼스 조각 → 표시된 새 중립어의 용어 순위를 적용한다.
6. 상기, 제1·제2, 방향 기준, 새 조어, 직접 관계 술어, 기능과 구조의 대응을 구체화한다.
7. 종속항의 인용 줄·새 한정·중심 한정축과 부모항 체인을 원문 기준으로 검사한다.
8. 코퍼스를 기본 문맥이나 전체 청구항의 긍정 정답으로 쓰지 않는다. 국소 통사 조각은 최대 1~2개, 해당 EX-ID·구절·범위 불변 기록이 있어야 한다.
9. 실제 원자료의 누락을 예시로 채우지 않고, 스타일로 기술 범위·주골격을 바꾸지 않는다.
