# OA 300건 그래프와 OA 도구

등록 특허 300건의 심사 경과 요약을 사례 기록으로 바꿔, 명세서·청구항 작성 단계를 역산해 보는 참고 층이다. 발명 원자료·게이트·근거가 아니다.

## 데이터

| 파일 | 내용 | git |
|---|---|---|
| `graph/oa300/kg_dump.json` | Neo4j GraphRAG 데이터셋 `kr-oa-300`을 `kg_search`로 모은 덤프: 사례별 마크다운 청크 300개 + 개체 관계 | 제외 |
| `docs/oa300-records.json` | 덤프를 낱말 규칙으로 나눈 사례 기록(`claim_agent/graph/oa300.py`) | 포함 |

- 출처: 등록 2025-11~2026-11 한국 특허 300건(IPC 섹션별로 고르게 뽑힘), 의견제출통지 380건. 사례 요약은 모델이 썼고, **의견서 본문이 없어** 대응 방식은 최초·등록 독립항 요지 비교로 추정한 값이다.
- 검색 도구가 청크 본문을 1,500자에서 잘라 97건은 끝부분(출원인 대응·등록 독립항 요지)이 비어 있다. 그 사례는 그래프 관계(ADDED_FEATURE·OVERCOME_BY)로 더한 구성과 대응 방식을 채우고 `filled_from_graph`에 적는다. 원본 마크다운 300건을 얻으면 같은 형식으로 덤프를 만들어 다시 가져오면 된다.
- 등록된 건만 있어 생존 편향이 있다. 수는 낱말 규칙으로 센 미검토 값이다.

```bash
claim-agent graph oa import
```

```bash
claim-agent graph oa guide --write
```

```bash
claim-agent graph oa tool oa_dependents --text "B65H 스풀 레이스" --claim-file claims.txt
```

`import`는 덤프를 기록으로, `guide --write`는 `sources/10_심사이력_경험기준.md` 맨 아래 생성 절(GENERATED:START/END)을 다시 쓴다. 시험(`tests/test_oa_tools.py`)이 기록 파일과 생성 절이 생성기 결과와 같은지 본다.

## 기록 한 건

`reg_no`·`title`·`subclass`·`oa_count`·`initial_claim`(최초 독립항 요지)·`granted_claim`(등록 독립항 요지)·`oas[]`(차수·심사국·거절 근거·인용문헌·등록 가능 청구항·거절이유 요약·심사관 보정 시사·최후통지)·`strategies`(추정 대응 방식)·`added[]`(등록 독립항에 더한 구성)·`added_types`(낱말 규칙 유형: 수치·범위, 위치·결합·배치, 단계·순서, 조건·모드·판단, 형상, 재질·성분, 데이터·신호, 목적·용도, 구성요소 추가, 명확화·삭제)·`disclosed`(그래프가 인용문헌의 개시 내용으로 정리한 개념, 관계가 들어온 사례만).

## OA 도구 (웹 작업 도구 패널)

두 작업 방식 모두에서 쓴다. 모델·Jev를 부르지 않는다. 고른 대상 청구항이 있으면 그 청구항과 입력창의 분야·기술 낱말(IPC 서브클래스가 있으면 함께)을, 없으면 입력창의 말만 본다. 가까운 사례는 글자 2-gram TF-IDF와 IPC 서브클래스로 고르며 의미 검색이 아니다.

| 도구 | 원래 목록 | 보이는 것 |
|---|---|---|
| 종속항 역산 `oa_dependents` | 9 | 분야별 종속항 병합·등록 가능 청구항 적시 비율, 더한 구성 유형 분포, 내 종속항이 그 유형을 덮는지, 가까운 사례의 최초 독립항 → 더한 구성 |
| 독립항 갭 `oa_gap` | 10 | 분야별 신규성·진보성 거절 비율, 1회 등록·최후통지, 신규성 거절된 넓은 독립항의 전형(최초 요지·심사관이 본 인용발명·등록 요지) |
| 수치한정 뒷받침 `oa_numeric` | 11 | 내 문언의 수치 구절, 수치가 다투어진 방식(겹침·최적화·불명확·뒷받침) 통지 수, 명세서 체크리스트, 내 수치와 가까운 사례 |

답은 `판례 도구`와 같은 경로(`/api/caselaw`, 메시지 `mode: CASELAW`)로 대화에 보이지만 `web.conversational()`이 모델이 읽는 대화 기록·원자료·참조·검수 대상에서 뺀다. 도구 추천(`tool_advice`)과 평가 폼도 이 세 도구를 안다.

## 쓰지 않는 곳

- 독립항을 설계·작성·스타일 조정하는 역할에는 이 기록도, 이 기록으로 센 수도 넘기지 않는다(sources/10 `독립항 생성에 쓰지 않는 이유`). 독립항 갭 도구는 사용자가 넓이의 감각을 보는 참고일 뿐이다.
- 이 기록으로 한정·종속항 후보를 만들거나 08 게이트·`exam_pattern` 분류를 바꾸지 않는다. 분류 근거는 현재 발명의 원자료 문장뿐이다.
