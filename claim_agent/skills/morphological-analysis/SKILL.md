# 형태학적 분석 (Morphological Analysis)

목표는 정답이 아니라 **기존 해에서 멀리 떨어져 있으면서도 모순 없이 성립하는 해를 찾을 수 있는 조합 공간을 만드는 것**이다.

- **해(解):** 문제에 대한 해결안 하나. 상자에서는 축마다 값을 하나씩 고른 조합 하나.
- **축:** "무엇을 정해야 하나"(결정 지점). **값:** 그 결정에서 고를 수 있는 선택지.
- **핵심 원리:** 조합의 창의성 상한은 축과 값을 세울 때 이미 정해진다. 통상적인 분해로 만든 축은 이미 아는 선택지의 재조합만 낳는다. 그래서 축은 주제를 빠짐없이 분해하는 것이 아니라, **당연하게 고정돼 있던 것을 변수로 바꾸는 방향**으로 기획한다.
- **숨은 전제 = 기존 해들이 전부 같은 값을 고르고 있어서 축으로 보이지 않던 축**이다. 이를 드러내 다른 값을 고르면 해가 크게 멀어진다.

단계(발산 → 상자+CCA → 평가)를 나누고, 사용자가 다음 단계를 요청하기 전에는 넘어가지 않는다.

- 외부 MCP는 쓰지 않는다. 계산이 필요할 때만 Python을 쓴다(아래 '계산 경로').
- 공지 종속항을 도면 특징과 결합해 청구항을 개선하는 작업은 `patent-claim-morphology` 스킬을 따른다.

## 0. 시작

1. **주제 문장:** `[대상]의 [무엇]을 [목적]을 위해 탐색` 형식으로 한 줄 잡는다.
2. **해 단위:** "해 하나 = 무엇의 한 가지 안"인지 한 문장으로 적는다. 해석이 여러 갈래면 2~3안을 보여주고 고르게 한다.
3. **목표 유형:** 하나를 고른다.
   - 창의적 대안·해 공간 지도 → 기본 발산(아래 1단계)
   - 원인 분석·맹점 탐지처럼 가설 목록 자체가 산출물 → `/가설` 모드
   - 시나리오 → 기본 발산, 외부 변수를 전제 축 후보로 우선 검토
4. 주제 문장·해 단위·목표가 빠져 있으면 가장 그럴듯한 안으로 진행하고, 1차 출력 첫줄에 어떻게 잡았는지 밝힌다. 묻느라 멈추지 않는다.
5. **목표 고정:** 원래 목표, 완료 기준, 유지할 제약을 회차가 바뀌어도 계속 들고 간다. 하위 문제는 원래 목표를 대체하지 않는다. 사용자가 범위를 바꾸면 새 범위로 축을 다시 설계하되, 유지 제약과 직전 기각 사유는 이어받는다.
6. 정답이 명확한 사실 질문이면 사실을 한 줄로 답하고, 그 주변의 열린 질문으로 발산한다.
7. 사용자가 저장한 `[MA-AXES]` 블록을 붙여넣으면 그 상태에서 시작한다.

## 1단계: 발산 (/발산) — 기존 해에서 역으로 축을 기획한다

### 1-1. 기존 해 나열
- 축을 생각하기 전에 기존 해를 **10~20개** 나열한다. 각 한 줄, ID(S1, S2…)를 붙인다.
- 포함할 것: 사용자의 현재 안·첫 직관, 흔한 관행안, 경쟁·시장에 나와 있는 안, **인접 분야에서 같은 목적을 푸는 안**.
- 비슷한 해를 많이 모으기보다 서로 다른 해를 모은다. 많이 모을수록 공통점이 우연이 아니라 분야 전체의 전제라는 것이 드러난다.
- 최신 시장·제품·사례가 필요한 주제면 검색으로 보강한다.

### 1-2. 차이 축 추출
- 기존 해들이 **서로 다르게 결정한 지점**을 축으로 뽑는다. 각 축에 ID(A, B, C…)를 붙인다.
- 축마다 기존 해들이 고른 값을 적고 `●`로 표시한다.

### 1-3. 전제 축 추출 (창의성의 주 원천)
비교로는 차이만 보인다. 기존 해가 **전부 공유하는 것**을 따로 찾아 축으로 바꾼다. 아래 질문을 강제로 거친다.
- 모든 기존 해가 공유하는 것은?
- 이게 없으면 성립이 안 된다고 다들 믿는 것은?
- 누가 / 언제 / 어디서 / 무엇으로 / 얼마나 / 어떤 순서로가 암묵적으로 고정돼 있나?
- 비용을 누가 내는가, 이득을 누가 가져가는가가 고정돼 있나?
- 다른 분야는 같은 목적을 어떻게 푸는가? 그 방식이 여기서 당연히 배제된 이유는?
- 시간(단기·장기·지연), 스케일(개인·조직·시스템), 측정·정의 방식이 고정돼 있나?

규칙
- 찾은 공통점을 축으로 바꾸고, 기존 해가 고른 단 하나의 값을 `●`로, 대안 값을 채운다.
- **전제 축은 최소 2개** 만든다.
- **목적은 고정하고 수단에 깔린 전제만 푼다.** 목적 자체를 바꾸는 전제(예: "애초에 이 문제를 풀 필요가 있나")는 축에 넣지 않고 '목적 수준 전제' 메모로만 남긴다. 넣으면 질문을 벗어난다.

### 1-4. 값 채우기
- 축마다 **기존 값(`●`) + 새 값(`○`)**을 함께 둔다. 기존 값을 버리지 않는다. 창의적인 해는 대개 몇 축은 익숙한 값, 한두 축에서 크게 벗어난 값의 조합이다.
- 새 값의 출처: 극단값 / 없음(0) / 역전값 / 다른 분야 차용값 / 주체·시점·장소 이동
- 축당 값 3~6개. 전제 축은 새 값 위주로 채운다.
- 값은 상호배타적이어야 하고 "기타"는 넣지 않는다. 새 값이 기존 값의 말만 바꾼 변형이면 합친다.

### 1-5. 축 점검
- 독립성: 한 축이 다른 축으로 설명되면 합친다.
- 추상 수준: 같은 상자 안의 축은 수준을 맞춘다.
- 해 단위 대응: 축마다 "이걸 안 정하면 해 하나가 완성되지 않는다"가 성립하는지 본다.
- 기존 해 표현 가능성: 기존 해 각각을 축별 값의 조합으로 표현할 수 있어야 한다. 안 되면 축이나 값이 빠진 것이다.

### 1단계 출력
1) 잡은 주제 문장 / 해 단위 / 목표 (한 줄씩)
2) 기존 해 목록 (S1~Sn)
3) 축 표: `ID | 축 | 종류(차이/전제) | 기존 값 ● | 새 값 ○`
4) 기존 해 → 조합 대응 (예: S3 = A1·B2·C1·D1)
5) 목적 수준 전제 메모 (축에서 뚜 것)
6) 원거리 조합 예시 3~5개: 모든 기존 해와 3축 이상 다른 조합. 공간을 보여주는 예시일 뿐 평가·랭킹이 아니다.
7) **축 확정 안내:** 상자에 쓸 축을 5~7개로 골라 달라고 요청한다. 전제 축이 최소 1~2개 남도록 추천 후보와 이유를 짧게 제시한다. 2단계는 사용자가 축을 확정한 뒤에 진행한다.
8) `[MA-AXES]` 블록

### 1단계 규칙
- 근거·통념·확률·현실성을 이유로 값을 제거하지 않는다. 제거는 정의상 불가능한 것과 의미가 같은 중복만.
- 랭킹·채택·결론·"가장 유력한" 표현을 쓰지 않는다.
- 통상적인 분해 범주(구성요소·원인·조건…)를 훑어서 축을 만들지 않는다. 축은 기존 해의 차이와 공통 전제에서 나온다.

## /가설 모드 (가설 목록이 산출물일 때만)

원인 분석·맹점 탐지처럼 가설 목록 자체가 필요할 때 `/가설`로 실행한다. 창의적 대안 탐색에는 쓰지 않는다.
1. 축은 1단계와 같은 방식으로 만든다. 원인 분석에서는 '기존 해'를 '지금까지 의심한 원인·통념적 설명'으로 읽는다.
2. 단일 축 가설과 2~3개 축 조합 가설을 만든다.
3. 유형이 각각 최소 1개 이상 나오게 한다: 통념형 / 반대형 / 저확률형 / 역인과형 / 간접경로형 / 상호작용형 / 누락변수형 / 측정오류형
4. 기본 50개, 확장 2라운드(1-3의 전제 질문을 렌즈로 사용). 사용자가 지정하면 따른다.
5. 형식: `[축ID·유형] 조건/원인 → 결과 (경로)`. 무엇이 무엇에 어떻게 영향을 주는지 없는 문장은 쓰지 않는다.
6. 랭킹·결론 금지. 나열은 축·유형 순서로 한다. 끝에 커버리지 요약(빈 축 조합)을 붙인다.

## 2단계: 상자 + CCA (/상자)

1. **상자:** 확정된 축 × 값 표를 만들고(●/○ 표시 유지) 원시 조합 수(각 축 값 개수의 곱)를 계산한다.
2. **교차 일관성 평가(CCA):** 서로 다른 축의 값 쌍마다 판정한다.
   - `O` 공존 가능 / `X` 동시에 성립할 수 없음 / `△` 조건부
   - 모든 X와 △에는 이유를 한 줄씩 붙인다. △는 조건도 적는다.
   - X는 "비현실적"·"낯설다"가 아니라 "동시에 성립할 수 없음"일 때만 쓴다. 새 값(○)을 낯다는 이유로 X 처리하면 전제 축을 만든 의미가 사라진다. 애매하면 △.
   - 쌍이 많으면 X와 △만 나열하고 나머지는 O로 간주한다고 밝힌다.
3. **고차 금지 조건:** 쌍으로는 문제없지만 3개 이상이 함께일 때 모순인 조합은 따로 적고 이유를 붙인다.
4. **남은 공간:** X 쌍과 고차 금지 조건을 포함하는 조합을 빼고 남은 조합 수를 낸다. 규모에 따라 아래 계산 경로를 쓴다.
5. **기존 해와의 거리:** 남은 조합마다 가장 가까운 기존 해와 몇 축이 다른지(최소 거리)를 계산하고, 거리별 조합 수 분포를 보여준다.
6. **대표 구성:** 모든 기존 해와 **3축 이상 다른** 조합을 중심으로, 서로도 2축 이상 다른 구성 5~10개를 뽑는다. 각 구성에 가장 가까운 기존 해와 그 해에서 달라진 축을 표시한다. 다양성·거리 기준이지 랭킹이 아니다.
7. 조건을 만족하는 원거리 조합이 없으면 그대로 밝히고, 어떤 금지 조건이 원거리 조합을 막고 있는지 보여준다.

**출력:** 상자 표 → 원시 조합 수 → X/△ 목록(이유 포함) → 고차 금지 조건 → 남은 조합 수와 거리 분포 → 대표 구성 → `[MA-AXES]` 블록

## 계산 경로 (필요할 때만)

**도구 없이 진행:** 원시 조합이 수백 개 이하이고 대표 구성만 필요할 때.

**Python으로 계산:** 남은 조합·거리 분포를 정확히 내야 할 때, 원시 조합이 수천 개를 넘을 때, 점수로 상위안을 다양하게 뽑아야 할 때.
- `itertools.product`로 전체 조합을 만들고, X 쌍과 고차 금지 조건으로 걸러 정확한 개수를 낸다.
- 기존 해를 조합으로 넣고, 남은 조합마다 기존 해들과의 최소 해밍 거리(값이 다른 축 수)를 계산한다.
- 점수가 필요하면 값 점수(선호 값 +1~3, 불리한 값 -1)와 쌍 점수(핵심 조합 +2~4)를 더해 합산한다. 점수는 선호이지 확률이 아니다.
- 대표 구성·상위안은 탐욕 선택으로 뽑는다: 기존 해와의 거리 하한(기본 3)을 만족하는 것 중, 이미 고른 구성들과 최소 2칸 이상 다른 것을 차례로 고른다. 점수가 있으면 점수 순, 없으면 기존 해와의 거리가 먼 순으로 훑는다. 상위가 문언·표현 변형으로 몰리면 서로 간 최소 거리를 3으로 올린다.
- 원시 조합이 수백만 개를 넘으면 `pip install ortools --break-system-packages` 후 CP-SAT으로 푼다.
- 요청 개수보다 적게 나오면 "이 조건에서는 이게 전부"라고 그대로 밝히고, 기준(거리, 금지 조건)을 낮출지 묻는다.
- 상위가 한두 계열에 몰리면 원인(점수 설계, 다양성 기준)을 설명하고 재실행을 제안한다.

## 3단계: 평가 (/평가)

- 사용자가 `/평가` 또는 "평가 시작"을 명시했을 때만 실행한다.
- 평가 기준을 먼저 제안하고(예: 실현성, 영향도, 비용, 기존 해와의 거리) 사용자가 고르거나 수정하게 한다. 기준이 이미 주어졌으면 바로 진행한다.
- 구성별 점수와 근거를 표로 먼저 내고, 그다음에 상위안과 결론을 말한다.
- 각 상위안에 필요한 가정과 확인할 근거를 함께 적는다. 조합이 조건을 만족한다는 것이 실제 성공을 뜻하지는 않는다.
- 사전 부검 등 다른 판단 스킬과 연결해도 된다.

## 대화 중 명령

- `더`: 비어 있는 조합·값 중심으로 추가 생성
- `해 추가: …`: 기존 해를 추가하고 축·전제를 다시 점검
- `전제 더`: 1-3 질문을 더 돌려 전제 축 후보 추가
- `축 추가: …` / `축 제거: …` / `값 추가: 축ID …`: 상자 수정 후 재조합
- `좁혀: …`: 해당 범위로 제한해 재발산
- `주제: …`: 주제 교체

## [MA-AXES] 블록 (재사용 형식)

1·2단계 출력 끝에 항상 붙인다. 사용자가 저장했다가 다음 대화에 붙여넣으면 이어서 작업한다.

```
[MA-AXES]
주제: …
해 단위: …
목표 유형: …
완료 기준: …
유지 제약: …
기존 해: S1=A1·B2·C1, S2=A2·B2·C1, …
A. 축이름 [차이]: ●값1 | ●값2 | ○값3
```

## 운영 기준

- 상자 규모: 축 5~7개(전제 축 1~2개 포함), 축별 값 3~5개. 4개 이하는 너무 단순하고, 8개 이상은 CCA 쌍이 폭증한다.
- 축이 10개를 넘으면 상자를 둘로 나눈다(예: 기능 상자, 비즈니스 상자).
- 남은 조합이 수천 개면 축을 줄이고, 몇 개뿐이면 값을 늘린다.

## 도메인 힌트 (해당 주제일 때만 참고)

- 제품 기획: 기존 해 = 경쟁 제품·대체재. 전제 후보 = 사용 주체, 사용 시점, 수익 방식
- 네이밍: 기존 해 = 같은 업계 이름들. 전제 후보 = 어근 언어, 의미 직접성, 음절 구조
- 원인 분석: `/가설` 모드. 기존 해 = 지금까지 의심한 원인
- 특허: 회피설계·선행기술 검색식 공간은 기존 해 = 공지 기술·경쟁사 구성. 청구항 개선은 `patent-claim-morphology`로 넘긴다.
