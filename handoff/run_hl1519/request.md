# 요청 (run_hl1519)

## 사용자 요청 원문
"15~19항 게이트 돌리고, 특히 연역 논증 오류, "대응하는"이라는 표현이 너무 읽는자를 헷갈리게 만드는 문제점을 개선해주길 원함."

## 분류
- request_mode: AUTHORING_DRAFT / authoring_scope: EXISTING_SET_EDIT
- 편집 대상: 제15~19항(번호·인용관계 유지: 15←14, 16←15, 17←16, 18←17, 19←18). 1~14항은 읽기 전용.
- 루트: BASELINE_SET — UNVERIFIED (제14항 독립항)
- dependent_set_id: DS-hl-ctrl-1519 / dependent_design_revision: dd1 / 목표 dependent_revision: dr1
- PRIOR_ART_SET: NONE / 정식 명세서 없음 / BUSINESS_CONTEXT 없음

## 요청 초점 (사용자 지시)
1. 연역 논증 오류: 기능·결과를 구성의 귀결로 적은 구절(…됨에 따라 …접속되며, …을 통하여 개별적으로 제어, …를 거쳐 전달되는 신호를 수신 등)이 적힌 구성·관계만으로 연역되어야 한다(FUNCTION_DEDUCTION_GATE).
2. "대응하는" 남용: 읽는 사람이 어느 모듈의 어느 전달부인지 헷갈린다. "대응하는"을 짝 관계가 문면에서 바로 보이는 구조(예: 모듈 자신이 갖는 부재, 그 모듈이 결합되는 자리)로 바꿀 것.

## 오케스트레이터 관찰 (참고 — 원자료·근거 아님, 따를지는 계약이 정함)
- O-1 (15항) "각각 대응하게 배치되는 복수의 제1 전력 전달부" — '대응'이 위치인지 개수인지 전기적 짝인지 정의되지 않음. 결합에 따른 접속이 연역되려면 제1 전력 전달부가 그 모듈이 결합될 때 그 모듈의 제2 전력 전달부가 닿는 자리에 있다는 관계가 필요.
- O-2 (15항) "…를 통하여 개별적으로 제어" — 모든 제1 전력 전달부가 하나의 공통 배선에 묶여 있어도 문언을 충족하는 반례 모델이 가능. 제어부가 각 제1 전력 전달부와 따로 연결된다는 전제가 없음. 이 전제가 원자료에 있는지(도면 7.webp의 받침별 단자 블록, 슬라이드 "독립적인 작동")는 설계자가 판단.
- O-3 (15항) 도면상 제1 전력 전달부는 받침 4곳을 가진 빔 하나다(4.webp, 7.webp). "복수의 제1 전력 전달부"로 쓰면 빔 하나 실시가 포섭되는지 독자마다 갈림(이전 5항 dr1 syntax B-2와 같은 유형). 
- O-4 (16항) "가열 부재 측에 접속되는" — '측'의 대상이 불명확. 분해도 6.webp에서 리드 단자가 무엇에 연결되는지 확인 필요.
- O-5 (17~19항) 전원/신호 포고 핀 구분, 서브 단자–신호 포고 핀 연결, 제어부의 신호 수신은 사용자 초안에만 있음. 신호를 만드는 소자가 문언·원자료에 없어 "신호를 수신하고 그에 기초해 제어"가 연역되지 않을 수 있음(서브 단자가 아무것에도 연결되지 않은 반례).
- O-6 (18항) "상기 복수의 리드 단자는, 상기 복수의 포고 핀보다 개수가 많고, … 서브 단자를 포함" — 개수 한정의 기술적 이유가 문면에 없음. 16항 "일부가 포고 핀과 연결" + 18항 "서브 단자는 신호 포고 핀과 연결"이면 서브 단자도 그 '일부'에 속하는지 갈림. 제5항(다른 가지)의 서브 단자는 "포고 핀과 전기적으로 분리"로 반대 정의.
- O-7 (19항) "복수 개의 히트리드 모듈 각각이 대응하는 상기 서브 단자로부터 … 상기 신호 포고 핀이 대응하는 상기 제1 전력 전달부" — 주어·소유 관계가 엉킴.
- O-8 표기: "복수 개의"/"복수의" 혼용.
